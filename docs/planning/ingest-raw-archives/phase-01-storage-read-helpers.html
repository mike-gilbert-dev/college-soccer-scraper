Phase 1: Storage Read Helpers

Project: Ingest Raw Archives Phase: 1 of 3 Depends on: None (first phase)

Overview

Adds two new read functions to src/lib/server/ncaa-archive.ts that the ingest endpoint will use to retrieve full contest and box score data from Storage. This phase is purely additive — no existing functions are modified, no endpoints or UI are touched.

What Will Be Built

Two new exported functions appended to src/lib/server/ncaa-archive.ts, plus a new exported type. Add a new import of NcaaContest and NcaaBoxScore from $lib/server/ncaa-api at the top of the file.

1. readGameContests()

Downloads the game JSON file for one date and returns the full NcaaContest[] array (not just the contest IDs). Returns [] if the file does not exist.

export async function readGameContests(
  sportCode: string,
  division: number,
  seasonYear: number,
  contestDate: string // YYYY-MM-DD
): Promise<NcaaContest[]> {
  const path = archivePath(sportCode, division, seasonYear, contestDate);
  const { data, error } = await supabaseAdmin.storage.from(BUCKET).download(path);
  if (error) {
    if (
      error.message.includes('Not Found') ||
      error.message.includes('404') ||
      error.message.includes('Object not found')
    ) return [];
    throw new Error(`Storage download failed for ${path}: ${error.message}`);
  }
  const text = await (data as Blob).text();
  const json = JSON.parse(text) as { data?: { contests?: NcaaContest[] } };
  return json?.data?.contests ?? [];
}

2. StoredBoxScoreResult type + readStoredBoxScore()

Downloads a box score JSON file and returns a discriminated result that distinguishes "file not found" from "file found but no box score data." The caller uses this distinction to decide whether to skip player stats (not found) or delete existing player stats (found but empty).

export type StoredBoxScoreResult =
  | { fileFound: false }
  | { fileFound: true; boxScore: NcaaBoxScore | null };

export async function readStoredBoxScore(
  sportCode: string,
  division: number,
  seasonYear: number,
  contestId: string | number
): Promise<StoredBoxScoreResult> {
  const path = boxScorePath(sportCode, division, seasonYear, contestId);
  const { data, error } = await supabaseAdmin.storage.from(BUCKET).download(path);
  if (error) {
    if (
      error.message.includes('Not Found') ||
      error.message.includes('404') ||
      error.message.includes('Object not found')
    ) return { fileFound: false };
    throw new Error(`Storage download failed for ${path}: ${error.message}`);
  }
  const text = await (data as Blob).text();
  const json = JSON.parse(text) as { data?: { boxscore?: NcaaBoxScore | null } };
  return { fileFound: true, boxScore: json?.data?.boxscore ?? null };
}
Two distinct nulls: { fileFound: false } means no file was ever saved for this contest — skip player stats, leave the DB unchanged. { fileFound: true, boxScore: null } means the file exists but the NCAA returned no box score data (common for scheduled games) — the ingest endpoint should delete any existing player_game_stats rows for this game to keep the DB in sync with the files.

Implementation Notes

  • Add import type { NcaaContest, NcaaBoxScore } from '$lib/server/ncaa-api'; at the top of ncaa-archive.ts. These types are already defined and exported from that module — no duplication.
  • The "not found" error handling in readStoredBoxScore must check for all three strings ('Not Found', '404', 'Object not found') — same pattern used in the existing readGameContestIds function.
  • The data path for the box score file is raw.data.boxscore, not raw.boxscore. Match the shape of the archived files exactly.
  • readGameContests is intentionally separate from the existing readGameContestIds. Both can coexist — readGameContestIds is used by the box score archiver, readGameContests is used by the ingest endpoint.
