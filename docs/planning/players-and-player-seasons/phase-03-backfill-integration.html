Phase 3: Backfill Integration

Project: Players & Player Seasons  |  Depends on: Phase 1 (fetchBoxScore types), Phase 2 (schema)

Extend the existing backfill endpoint to optionally scrape player stats from box scores. When includePlayerStats: true is sent, the backfill fetches a box score for each final game and upserts players, player_seasons, and player_game_stats. Also update upsertTeamSeason to record sport_code (used by the teams page in Phase 4). Player stats are off by default to keep the standard backfill fast.

Completion Criteria

  • Backfill route accepts includePlayerStats?: boolean (default false) in the JSON request body
  • upsertTeamSeason helper updated to pass sport_code in the team_seasons upsert call
  • When includePlayerStats is true, the route calls fetchBoxScore(ncaa_contest_id) for each game with status 'final'
  • For each player in the box score: upserts players (on conflict ncaa_player_id), then player_seasons (on conflict player_id, team_season_id), then player_game_stats (on conflict player_season_id, game_id)
  • Each box score fetch has a 1-second delay (await sleep(1000)) to respect rate limits
  • Results object includes playersUpserted: number and playerStatsUpserted: number counters
  • Box score fetch errors are caught per-game, logged to scrape_log, and do not abort the rest of the backfill
  • Admin "Scraper" tab has a checkbox "Include player stats (slower — 1 box score call per game)" bound to the includePlayerStats request flag
  • Admin results panel shows playersUpserted and playerStatsUpserted when they are non-zero
  • The description text in the Scraper tab is updated to mention that player stats require the box score endpoint

Implementation Notes

Rate limiting context

The existing backfill makes 1 API call per date (GetContests_web). With player stats enabled, it makes 1 additional call per final game on that date. A busy Saturday in DI Men's might have 40+ games, adding ~40 extra seconds per date. Recommend keeping limit to 5–10 dates per run when player stats are enabled.

4. Player stats upsert helper

Add this helper function inside the POST handler (alongside upsertTeamSeason):

async function upsertPlayerGameStats(
  contestId: string,
  gameId: number,
  homeTeamSeasonId: number,
  awayTeamSeasonId: number
): Promise<{ playersUpserted: number; statsUpserted: number }> {
  const boxScore = await fetchBoxScore(contestId);
  let playersUpserted = 0;
  let statsUpserted = 0;

  for (const team of boxScore.teams) {
    const teamSeasonId = team.seoname === /* homeData.seoname — pass as param */ ?
      homeTeamSeasonId : awayTeamSeasonId;
    // Note: pass homeTeamSeoname and awayTeamSeoname as params to resolve this

    for (const player of team.players) {
      // Upsert player master record
      const { data: playerRow } = await supabaseAdmin
        .from('players')
        .upsert(
          { ncaa_player_id: player.playerId, name: player.name },
          { onConflict: 'ncaa_player_id' }
        )
        .select('id')
        .single();
      if (!playerRow) continue;
      playersUpserted++;

      // Upsert player_season
      const { data: playerSeason } = await supabaseAdmin
        .from('player_seasons')
        .upsert(
          {
            player_id: playerRow.id,
            team_season_id: teamSeasonId,
            jersey_number: player.uniformNumber ? parseInt(player.uniformNumber, 10) : null,
            position: player.position ?? null,
            class_year: player.classYear ?? null
          },
          { onConflict: 'player_id,team_season_id' }
        )
        .select('id')
        .single();
      if (!playerSeason) continue;

      // Upsert player_game_stats — map API stat fields to DB columns
      const s = player.stats;
      const { error: statsErr } = await supabaseAdmin
        .from('player_game_stats')
        .upsert(
          {
            player_season_id: playerSeason.id,
            game_id: gameId,
            minutes_played:   s.minutesPlayed   ?? null,
            goals:            s.goals            ?? 0,
            assists:          s.assists          ?? 0,
            shots:            s.shots            ?? 0,
            shots_on_goal:    s.shotsOnGoal      ?? 0,
            fouls_committed:  s.foulsCommitted   ?? 0,
            yellow_cards:     s.yellowCards      ?? 0,
            red_cards:        s.redCards         ?? 0,
            gk_saves:         s.gkSaves          ?? null,
            gk_goals_against: s.gkGoalsAgainst   ?? null,
            gk_shutout:       s.gkShutouts != null ? s.gkShutouts > 0 : null
          },
          { onConflict: 'player_season_id,game_id' }
        );
      if (!statsErr) statsUpserted++;
    }
  }
  return { playersUpserted, statsUpserted };
}
The API stat field names (minutesPlayed, shotsOnGoal, etc.) are based on the TypeScript interfaces from Phase 1. Update these mappings if the actual field names differ. Specifically verify: goals, assists, shots, minutes, fouls, cards, GK stats.
