Phase 7: Leaderboard

Project: Pick'em Phase: 7 of 7 Depends on: Phase 6 complete
⚠️ Prerequisite: Phase 6 (User Profile) must be complete — the leaderboard links into profile pages and reuses its aggregate patterns.

Overview

The competitive surface that ties the feature together: a public leaderboard at /pickem ranking users by total wins and by win percentage, filterable by season and sport.

This is the last phase. When it ships, the loop is closed — pick on the scoreboard, get graded automatically, track yourself on your profile, compare against everyone else here.

📄 See pickem.md — "Public read surfaces" has the get_leaderboard signature and explains why leaderboards are security definer functions rather than views.

What Will Be Built

1. get_leaderboard(...)

get_leaderboard(
  p_season_id  bigint,
  p_sport_code text,
  p_board      text,     -- 'wins' | 'pct'
  p_min_picks  int,      -- qualifier, default 25
  p_limit      int,
  p_offset     int
) returns table (
  rank int, username text, wins int, losses int,
  voids int, graded int, win_pct numeric
)

security definer, granted to anon and authenticated. Joins picks to public_profiles, so users who haven't confirmed a generated username are excluded automatically.

  • 'wins' board — ranked by raw win count, no minimum.
  • 'pct' board — ranked by win %, only users with graded >= p_min_picks.
✅ The qualifier is 25 graded picks per season per sport. This is a starting guess, not a derived number — revisit once there's real usage data. If most active users finish with 60+ graded picks, 25 is too permissive. Keep it a parameter so it can change without a migration.

2. get_user_leaderboard_position(...)

Returns the signed-in user's rank and how many more graded picks they need to qualify for the percentage board. This powers a personal strip above the table so an unqualified user still sees where they stand — the reason two boards were chosen over a single one.

3. /pickem route

  • Board tabs — Most Wins / Best Win %
  • Season + sport selectors — matching the /scores control conventions
  • Table — rank, @username (linking to /u/[username]), W-L, win %, graded count. Highlight the signed-in user's own row.
  • Personal strip — "You're 7th with 34-19 (64.2%)" or "You need 11 more graded picks to qualify"
  • Pagination — explicit limit/offset, 50 per page

Implementation Notes

Paginate explicitly. PostgREST caps responses at 1000 rows and truncates silently rather than erroring. The leaderboard is the most likely place in this feature to hit that ceiling as usage grows — the limit/offset parameters aren't optional polish.

Use rank(), not row_number(). Users with identical records must share a rank. With small user counts, ties will be common and arbitrary ordering looks broken.

Aggregates only. Same constraint as Phase 6 — the leaderboard exposes totals, never another user's individual picks. Deliberately verify this: it's the last place a security definer function could leak.

Watch the win % sort with zero denominators. A user whose graded picks are all voids has wins + losses = 0. They must be excluded from the percentage board rather than sorting as 0% or NULL-first.

Performance. The aggregate scans picks grouped by user; picks_user_season_idx covers it. Check explain analyze at realistic volume (thousands of picks) — if it degrades, materialize per-user season totals rather than adding caching to the page.

How to Validate

  1. Seed 5–6 test users with varied volumes — some above 25 graded picks, some below, at least two with identical records, one with only voids. Run grade_picks().
  2. Visit /pickem and cross-check the Most Wins board: 
    select pp.username,
       count(*) filter (where p.result='win')  as wins,
       count(*) filter (where p.result='loss') as losses
from picks p join public_profiles pp on pp.id = p.user_id
where p.season_id = <id> and p.sport_code = 'MSO'
group by 1 order by wins desc;
  3. Switch to Best Win % — confirm sub-25 users are absent and ordering is by percentage.
  4. Confirm the two identical-record users share a rank, and the voids-only user is off the percentage board.
  5. Sign in as a qualified user → own row highlighted, personal strip shows the rank. Sign in as an unqualified one → strip shows picks needed.
  6. Click a username → lands on their profile.
  7. Switch season and sport; both boards update.
  8. Page through results; confirm no duplicates or gaps at the boundary.
  9. Sign out and reload — the board still renders.
  10. Confirm an unconfirmed backfilled account is absent from both boards.
  11. Attempt to read another user's picks through every new function — none should return one.
  12. Fetch /sitemap.xml and confirm /pickem is listed.
  13. Check 375px, light and dark mode.
  14. Run explain analyze on get_leaderboard at seeded volume.
  15. Full end-to-end: as a fresh user — register with a username, pick games on /scores, let grading run, view /u/[username], find yourself on /pickem.
  16. Clean up test data. Run npm run check and npm run test.
