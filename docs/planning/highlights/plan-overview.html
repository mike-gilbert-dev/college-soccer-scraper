Highlight Video Ingestion

A curated list of YouTube channels, checked on a schedule. Videos that can be matched to a sport, a team and a game get stored and embedded on the game page, the team page, and a new /highlights.

01 The whole thing

  1. Curate the channels

    One table of approved channels — NCAA, conferences, schools. You fill it; nothing enters the system from anywhere else.

  2. Check them on a schedule

    One cron job reads each channel's uploads feed and keeps what looks like soccer.

  3. Match what you can

    Sport, gender, team, game — in that order, stopping wherever the evidence runs out. What doesn't match waits for review instead of disappearing.

  4. Show it in three places

    Game page, team page, and /highlights newest-first.

That's the system. Everything below is how each step works — two Postgres tables, two edge functions, three routes and one admin screen. No new infrastructure, no LLM, no new external dependency beyond a YouTube API key.

02 The channel list

Curating by hand is the design, not a shortcut around one. It is the only way “official sources only” can actually be guaranteed, and it's cheap: about 260 rows — ~190 school channels, ~30 conference, the NCAA's, and the handful of schools with a dedicated soccer channel. An afternoon, then near-zero maintenance.

Why it can't be automated: youtube.com/@bigten is a rapper

Not the Big Ten Conference — it resolves cleanly to a real music channel. Anything that builds a handle from a school or conference name and trusts the result will eventually publish a stranger's videos under a conference's name. Store the UC… channel id, verified by eye once; keep the handle for display only, since handles can be reassigned. 

CREATE TABLE video_sources (
  id               bigserial PRIMARY KEY,
  channel_id       text NOT NULL UNIQUE,      -- 'UC...' — the stable id
  handle           text,                      -- '@ncstateathletics', display only
  title            text,                      -- 'NC State Athletics'
  owner_kind       text NOT NULL CHECK (owner_kind IN ('ncaa','conference','school')),
  team_id          bigint REFERENCES teams (id),
  conference_id    bigint REFERENCES conferences (id),
  sport_code       text,                      -- set ONLY for a soccer-specific channel
  soccer_playlists text[],                    -- see §03
  is_active        boolean NOT NULL DEFAULT true,
  last_checked_at  timestamptz,               -- stalest-first queue
  created_at       timestamptz NOT NULL DEFAULT now()
);

Two shortcuts for filling it. Schools publish their channel in their own site chrome — NC State's schedule page carries youtube.com/@ncstateathletics in the footer, and you already archive 568 of those pages in the schedule-raw bucket. And game_streams already holds channel URLs schools published themselves: @pac12, @WesternMichiganBroncos, @GoMastodons, a few more. Both are just lists to paste and check — not code to write.

03 Checking for new videos

YouTube publishes a free uploads feed per channel — feeds/videos.xml?channel_id=UC… — returning the 15 newest videos with id, title, description, publish time and thumbnail. No key, no quota. That's the default path.

Where a school keeps a soccer playlist, poll that instead. NC State and Ohio State both have Men's Soccer and Women's Soccer playlists, and playlists.list costs 1 quota unit to find them. It's the better path where it exists: the sport comes stated by the school rather than guessed from a title, and you never have to filter football out because it was never in the list. Store the ids in soccer_playlists and re-check them each preseason.

One job, not a pipeline

video-sync does the whole loop: claim the stalest channels, read the feed or playlist, keep soccer candidates, match them, write rows. ~260 channels is well inside one invocation. Cron it a few times a day — twice is plenty, and one late-evening run catches same-night highlights.

The one caveat worth coding for: the feed holds only 15 entries, and a big athletics channel in football season can post that many in a week. Check a few times a day rather than daily, and when all 15 come back new, spend 1 unit on a playlistItems.list page to catch up.

04 Matching

Four questions, each answered by the cheapest evidence available, and the pipeline can stop after any of them:

QuestionAnswered byIf unanswered
Soccer? The playlist it came from, or soccer / msoc / wsoc / #NCAAWSoccer / ⚽ in title or description Discard — don't store it
Men's or women's? The playlist, the channel's sport_code, or the same tokens Hold for review
Which team? The channel — a school channel is a team link. Opponent from the title via opponentMatches() Hold for review (conference / NCAA channels)
Which game? That team's games in published_at −1..−14 days; the opponent name in the title picks between them Keep the team link — it still shows on the team page and /highlights

A highlight package goes up after the whistle and never before it, so matching backwards from the publish time excludes previews structurally. The window is wide — 14 days — because schools are not prompt: Denver posted its Cal Poly highlights 11 days after the match. A wide window is safe here only because the opponent name does the actual picking, which the measurement below says it can.

Measured, 36 schools, September 2026

Every game highlight found in a 30-day sample named both the sport and the opponent — “Match Highlights | Colgate Men's Soccer vs. American | 9.11.26”, “MSOC v Tulsa (4 SEP 26) - Highlights”, “St. Joseph's at Bucknell Women's Soccer Highlights 8-30-2026”. The terse, sportless title that worried an earlier draft of this plan turns out to be rare: schools that bother posting soccer highlights title them properly, and schedule-match.ts already handles this shape, abbreviations included.

So the ambiguous case — “Highlights vs. Purdue”, no sport, both teams playing that week — is real but uncommon. It goes to review, and the queue should be small.

Most soccer videos are not game highlights

In the same sample, only 41% were. The rest are postgame interviews, coach pressers, hype videos and vertical clips — real content, tied to a game, but not a highlight reel. Store content_kind and let each surface choose: the game page wants game_highlight, /highlights can carry more.

05 What gets stored

An embed needs only the video id. Everything else is for sorting, filtering and knowing the embed still works. One table, with the connections as columns rather than join tables — a video has one publisher, at most one opponent, at most one game. 

CREATE TABLE videos (
  id                bigserial PRIMARY KEY,
  youtube_id        text NOT NULL UNIQUE,      -- all the embed needs
  video_source_id   bigint NOT NULL REFERENCES video_sources (id) ON DELETE CASCADE,
  title             text NOT NULL,
  description       text,
  published_at      timestamptz NOT NULL,
  thumbnail_url     text,
  duration_seconds  int,                       -- from videos.list; RSS has none
  embeddable        boolean,                   -- embedding can be switched off

  -- the connections
  sport_code        text,                      -- 'MSO' | 'WSO' | NULL if unresolved
  content_kind      text CHECK (content_kind IN -- only 41% are highlights
                    ('game_highlight','clip','interview','hype','other')),
  team_id           bigint REFERENCES teams (id),
  opponent_team_id  bigint REFERENCES teams (id),
  game_id           bigint REFERENCES games (id) ON DELETE SET NULL,
  match_note        text,                      -- 'playlist + date + opponent'

  review_status     text NOT NULL DEFAULT 'ok'
                    CHECK (review_status IN ('ok','pending','rejected')),
  api_checked_at    timestamptz,               -- the 30-day clock, §06
  first_seen_at     timestamptz NOT NULL DEFAULT now()
);

CREATE INDEX videos_recent_idx ON videos (published_at DESC) WHERE review_status = 'ok';
CREATE INDEX videos_game_idx   ON videos (game_id)  WHERE game_id IS NOT NULL;
CREATE INDEX videos_team_idx   ON videos (team_id, published_at DESC);

Unmatched videos are rows with review_status = 'pending', not a separate queue table. Public pages filter on 'ok'; the admin screen lists 'pending'. Both schools may post their own cut of the same game — both rows are real, and the game page picks one (soccer-specific channel first, then home school, then longer).

Nothing here writes to games. A video links to a game that already exists or to no game at all. The NCAA feed stays the sole authority on which games exist, the same rule the roster and webstream pipelines follow.

A highlight is not a live stream

Worth stating because your own data already blurs it: game_streams holds 146 rows with a YouTube URL, and 33 of them are highlight packages — labelled “Highlights”, deep-linked to a single video, every one on a completed game. Schools publish the live link and the highlight link in the same schedule field and swap one for the other after the match.

So ~33 games on /scores currently show a “Watch” button that opens a highlight reel. Two consequences, both small: reclassify those rows on ingest so the two systems stop overlapping, and import them here as a starting set — they're highlight videos with a game_id already attached, courtesy of the schools themselves, which also makes them a ready-made test for the matcher.

06 Keeping it honest

YouTube's 30-day rule is not optional

Their Developer Policies require stored API data to be refreshed or deleted within 30 days, and require verifying in that window that a video hasn't been deleted. This is also just good hygiene — videos get made private, or have embedding switched off, and a dead embed is worse than no embed.

video-refresh is the second job and the cheapest thing here: videos.list takes 50 ids per call for 1 quota unit, so re-checking a few thousand videos costs about 60 units. Daily, oldest api_checked_at first. It stamps the clock, fills in duration_seconds and embeddable, and deletes rows whose videos are gone. Public queries filter embeddable AND api_checked_at > now() - interval '30 days', so a lapse degrades to showing nothing rather than to showing something broken.

Two other rules to keep in the code review: embed via the standard player, unmodified — no downloading or re-hosting — and use youtube-nocookie.com/embed/<id>.

07 The three pages

Render a thumbnail with a play button and swap in the iframe on click. One eager iframe is hundreds of kilobytes of third-party script before anyone presses play — on /highlights that's the difference between fast and not.

  • Game page — the video under the box score, with “also from” when both schools posted one. A single WHERE game_id = ?.
  • Team page — a highlights strip near the articles section, newest first, on team_id alone. Works before any game matching exists.
  • /highlights — everything, newest first, filtered by sport, conference, team and date. Paginate it: a season will pass 1,000 rows, and PostgREST truncates there silently.
  • /admin/videos — the channel list, the pending queue, and the share of completed games that have a video.

08 Build order

  1. Tables + the channel list. Two migrations, then fill video_sources by hand. Nothing is blocked behind this but everything depends on it.
  2. video-sync, matching down to the team. Skip game matching entirely at first — stop at “which team”.
  3. /highlights + the team strip. Real value, live, on team links alone. This is the point where you can see whether coverage is good enough to bother going further.
  4. Game matching + the game page + video-refresh + cron. The last mile, and the only part that needs the date window and the review queue.

Steps 1–3 are the bulk of the value and none of the difficulty — and the September 2026 measurement backs that ordering hard: about a third of school channels post game highlights at all, so /highlights and team pages will look healthy while game pages will have a video for perhaps one game in seven. Build the surfaces that fill up first.

09 Traps

Guessing a channel from a name
@bigten. Verify once by eye, store the UC… id.
Storing every upload from every channel
Each stored row carries the 30-day refresh duty. Filter to soccer at the gate — a football press conference has no business in this database.
Putting an uncertain match on a game page
A wrong highlight under a scoreline is worse than none. Team page and /highlights are forgiving; the game page isn't.
Trusting a stale playlist
A “Men's Soccer” list last touched in 2019 looks authoritative and returns nothing current. Check the newest item's date.
Eager iframes on a list page
Thumbnail plus play button; load the player on click.
search.list
100 quota units a call against a 10,000/day budget, and it returns unvetted channels — it breaks the budget and the curation rule at once. The fix for thin coverage is more approved channels.

11 Three questions

  1. A YouTube Data API key — a Google Cloud project with the YouTube Data API v3 enabled, stored as a Supabase edge secret. Needed for playlists and the 30-day refresh; the feeds themselves work without one.
  2. Do unmatched videos appear anywhere public? This plan says yes to /highlights and the team page once the team is known, no to the game page until reviewed.
  3. Shorts — the vertical clips the NCAA's channel mostly posts. Include on /highlights, or full highlights only?

Recommended: start step 1 now — the tables and the channel list don't depend on any of these answers.
