Phase 3: Admin Authoring UI

Project: News Section Phase: 3 of 6 Depends on: Phase 2 complete
⚠ Prerequisite: Phase 2 (Server Data Layer & Image Upload) must be complete — the editor consumes articles.ts helpers and the upload endpoint.

Overview

This phase gives you the tools to actually write articles: an admin index listing every article (any status), and a create/edit editor with a Markdown textarea + live preview, hero image upload, inline body-image upload, category, dek, editable publish date, the draft/published toggle, and the team/player tagging picker. Building the authoring side before the public side means there is real content to render in Phases 4–5. Crucially, this is where the “work on an article without it being displayed” requirement is satisfied via the draft state.

What Will Be Built

Routes (all under the admin-gated /admin tree)

  • src/routes/admin/news/+page.server.ts / +page.svelte — index table of all articles: title, status badge (draft = grey, published = green), category, published date, and Edit / View / Delete actions, plus a “New article” button. Uses listArticlesForAdmin().
  • src/routes/admin/news/new/+page.svelte & src/routes/admin/news/[id]/+page.server.ts / +page.svelte — the editor. New and edit can share one editor component. The [id] load uses getArticleForAdmin().

Editor component: src/lib/components/ArticleEditor.svelte

A Svelte 5 runes component ($props, $state, $derived). Fields:

  • Title (text). On blur, if slug is empty, auto-fill slug from title.
  • Slug (text, editable) with an inline “uniqueness” hint. Final uniqueness is enforced server-side via uniqueSlug.
  • Subtitle / dek (text).
  • Category (free-form text input).
  • Hero image (required to publish): file input → POSTs to /api/admin/news/upload → stores returned path+url, shows a thumbnail preview.
  • Body (Markdown <textarea>) with a live preview pane beside/below it. Preview should call the same renderMarkdown logic — do it via a tiny /api/admin/news/preview endpoint (debounced) OR import a client-safe render; to avoid shipping sanitize-html to the browser, a debounced fetch to a server preview endpoint is the clean choice.
  • Insert image button above the textarea: uploads via the same endpoint and inserts ![alt](url) at the cursor position.
  • Published date (datetime-local, editable — defaults to now when publishing; can be backdated).
  • Status toggle: Save as Draft / Publish (and Unpublish back to draft). Publishing is blocked client-side unless a hero image is set.
  • Related teams / players picker (see below).

Team / player tagging picker

A searchable multi-select. Teams list is small enough to load fully (the admin page already loads allTeams); players are ~thousands, so search them via a lightweight admin lookup endpoint (/api/admin/news/search-players?q=) returning id + name + team. Selected entities render as removable chips. On save, submit arrays of team_id / player_id.

Save path

Use SvelteKit form actions in +page.server.ts (?/save, ?/delete) that call createArticle/updateArticle/deleteArticle. Actions run server-side and are admin-gated by hooks. After save, redirect to the edit page (or index) with a success flash. The image uploads happen via fetch to the upload endpoint before form submit (so the form just carries the resulting URLs/paths).

Admin navigation

Add a News section to the admin sidebar in src/routes/admin/+page.svelte, following the existing “Rosters” pattern (a labelled group with links to separate routes rather than an activeView): links to /admin/news (“All Articles”) and /admin/news/new (“New Article”).

Implementation Notes

  • Flowbite Svelte components (Button, Input, Label, Select, Textarea, Badge, Alert) — same imports as src/routes/admin/+page.svelte. Consult docs/flowbite-svelte.md for quirks.
  • Design: dense, small text, red accent #e8463a (primary-500), light/dark support — match the admin page's Tailwind idioms exactly.
  • Preview XSS: the preview endpoint reuses renderMarkdown (already sanitizes), so preview and final render are identical.
  • Draft is the default for a new article — you can save and return to a half-finished article indefinitely without it ever appearing on the site.
  • Don't over-engineer the picker — a text input with a filtered dropdown and chips is enough. Reuse TeamLogo.svelte for team chips if convenient.

Completion Criteria

  • /admin/news lists all articles with status badges and New/Edit/View/Delete actions.
  • A new article can be created, saved as draft, reopened, and edited without ever being publicly visible.
  • Hero image upload works and previews; publishing is blocked until a hero image exists.
  • Inline “Insert image” uploads and inserts a working ![]() at the cursor.
  • Markdown live preview matches the eventual rendered output.
  • Category, dek, and an editable/backdatable publish date all persist.
  • Related teams and players can be added/removed and persist to the join tables.
  • Publish / Unpublish toggles status and sets published_at correctly on first publish.
  • Admin sidebar has a working News section; npm run check is clean.

How to Validate

  1. Sign in as admin, open /admin/news, click New Article.
  2. Fill title (watch slug auto-fill), dek, category; upload a hero image; write Markdown and confirm the live preview renders headings/bold/links.
  3. Use Insert image to upload an inline image; confirm ![]() is inserted and previews.
  4. Tag 1–2 teams and a player via the picker; save as Draft.
  5. Reload /admin/news — the article shows as Draft. Visit /news/<slug> in an incognito window and confirm it is NOT publicly reachable (404) — proving draft privacy (full public rendering is Phase 5, but the RLS gate already applies).
  6. Reopen, backdate the publish date, click Publish, and confirm status=published and published_at in the DB (execute_sql).
  7. Delete a throwaway article and confirm it disappears and its join rows are gone.
