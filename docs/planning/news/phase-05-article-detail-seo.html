Phase 5: Article Detail Page & SEO

Project: News Section Phase: 5 of 6 Depends on: Phase 4 complete
⚠ Prerequisite: Phase 4 (News Homepage) must be complete — its cards link into the detail pages built here.

Overview

This phase builds the full article reading experience at /news/[slug]: rendered Markdown body, hero image, metadata, related teams/players, and the SEO surface (title/meta/Open Graph tags + sitemap inclusion). It also wires an admin-only preview so drafts can be viewed in their final layout before publishing.

What Will Be Built

Route: src/routes/news/[slug]/+page.server.ts + +page.svelte

  • Load: fetch the article by slug. For public visitors use getPublishedArticleBySlug(locals.supabase, slug) (RLS ensures published-only). If not found → error(404).
  • Admin preview: if locals.isAdmin is true, fall back to getArticleForAdmin(slug) so an admin can open a draft at its real URL and see it exactly as it will publish. Render a clear “DRAFT — not publicly visible” banner in that case. Non-admins still get 404 for drafts.
  • Render body: the load (server) calls renderMarkdown(body_markdown) and passes sanitized HTML to the page; the component injects it with {@html ...}. (Safe because it's already sanitized server-side.)
  • Layout: hero image, category pill, title, dek, publish date, then the article body in a readable measure (prose-like styling — Tailwind typographic classes or hand-rolled to match the site). Related teams/players render as a “Related” footer with links to /teams/<ncaa_team_id> and /players/<ncaa_player_id>, reusing TeamLogo.svelte where it fits.
  • Back / more news: a link back to / and optionally a small “More news” strip reusing ArticleCard.svelte.

SEO & social

  • <svelte:head>: <title> = article title + “ — CollegeSoccer.IO”; meta description = dek; canonical URL.
  • Open Graph / Twitter card tags: og:title, og:description, og:image = hero_image_url, og:type=article, article:published_time.
  • For admin draft previews, emit <meta name="robots" content="noindex">.

Sitemap: src/routes/sitemap.xml/+server.ts

  • Add /scores to the static URLs (it moved in Phase 4).
  • Query published articles and emit a <url> per /news/<slug> with lastmod = updated_at. Drafts are excluded (query status='published').
  • Confirm / is still present (now News).
CLAUDE.md → SEO: the repo requires updating sitemap.xml/+server.ts when routes change. This phase satisfies that for the new /scores and /news/[slug] routes.

Implementation Notes

  • {@html} safety: only ever render the output of renderMarkdown (sanitized). Do not {@html} raw body_markdown or any unsanitized string.
  • Prose styling: if @tailwindcss/typography isn't installed, either add it or hand-style headings/paragraphs/lists/blockquote/img inside a scoped .article-body class. Check package.json before adding a dependency.
  • Images in body are absolute public Storage URLs from Phase 2 uploads; ensure they're responsive (max-width:100%; height:auto).
  • 404 correctness: a non-existent slug and an unpublished slug (for non-admins) must both return a real 404 status, not a 200 with empty content.

Key files to read before starting

  • src/routes/sitemap.xml/+server.ts — existing static + dynamic URL pattern to extend.
  • src/routes/games/[ncaa_contest_id]/+page.svelte (or teams/[ncaa_team_id]) — an existing dynamic route with <svelte:head> SEO to model.
  • src/lib/server/markdown.ts & articles.ts — the render + fetch helpers from Phase 2.
  • src/lib/components/TeamLogo.svelte, ArticleCard.svelte — reuse for related entities / more-news.

Completion Criteria

  • /news/<slug> renders a published article: hero, title, dek, date, sanitized Markdown body, and related teams/players with working links.
  • A non-existent or draft slug returns HTTP 404 for the public.
  • An admin visiting a draft slug sees the article with a “DRAFT” banner and noindex.
  • Head tags (title, description, canonical, OG image) are correct and populated from the article.
  • Homepage cards navigate to the correct detail pages.
  • Sitemap includes /scores and every published /news/<slug>, excludes drafts, and remains valid XML.
  • npm run check clean; body renders correctly in light/dark and on mobile.

How to Validate

  1. From /, click the featured article and a card; confirm each opens its /news/<slug> page with full body and correct related entities.
  2. View page source (or devtools) and confirm <title>, meta description, and og:image reflect the article.
  3. Hit a random bad slug (/news/does-not-exist) → confirm a 404 page and 404 status.
  4. As a non-admin/incognito, open a known draft slug → confirm 404. As admin, open the same slug → confirm it renders with the DRAFT banner and noindex.
  5. Paste a Markdown body containing an inline image, a link, and a list; confirm all render and the image is responsive.
  6. Load /sitemap.xml and confirm /scores and published article URLs appear and it's well-formed.
