Phase 6: Polish, Edge Cases & Hardening

Project: News Section Phase: 6 of 6 Depends on: Phase 5 complete
⚠ Prerequisite: Phases 1–5 complete — this phase hardens the finished feature end-to-end.

Overview

The feature is functional after Phase 5; this phase closes the gaps that make it production-ready: validation, error/empty states, image cleanup, accessibility, performance, and a final cross-cutting QA pass. Keep changes surgical — no new surface area, just robustness and finish.

What Will Be Built / Hardened

Validation & error handling

  • Server-side validation in the save action: title required, slug required + unique, hero image required to publish, category/dek length caps. Return field-level errors to the editor (Flowbite Alert / helper text), not raw 500s.
  • Upload endpoint: friendly JSON errors for oversized/wrong-type files; the editor surfaces them inline.
  • Guard the load-more endpoint against absurd limit values (clamp to e.g. 1–24) and negative offsets.

Empty / loading / end states

  • Homepage empty state (no published articles) reads well and doesn't break the featured layout.
  • Load more: spinner while fetching, graceful “You're all caught up” (or simply hide) at the end, error toast on failure with retry.
  • Cards with a missing/broken hero image fall back to a neutral placeholder (defensive even though hero is required).

Image lifecycle

  • When an article's hero image is replaced, optionally delete the old object from article-images to avoid orphans (best-effort; ignore failures). Inline body images are harder to track — document that they may orphan and leave a note; not blocking.
  • Confirm deleting an article does NOT need to delete images synchronously (acceptable to leave; note it).

Accessibility & responsive

  • All images have meaningful alt (hero uses title; require/encourage alt on inline uploads).
  • Cards are keyboard-focusable links with visible focus rings; category pills have sufficient contrast in both themes.
  • Featured + card grid verified at 320px, tablet, and desktop; article body measure stays readable (~65ch).
  • Semantic structure: article uses <article>, headings in order, published date in <time datetime>.

Performance

  • Confirm the articles_published_idx partial index is actually used by the list query (explain via execute_sql).
  • Card images: loading="lazy" + explicit width/height or aspect-ratio to prevent CLS.
  • Ensure the homepage load selects only card columns (not body_markdown) — verify no over-fetch.

Final QA sweep

  • Run get_advisors (Supabase MCP) for security/performance advisories on the new tables (e.g. missing RLS, unindexed FKs) and resolve anything flagged.
  • Full npm run check and a production npm run build succeed.
  • Update CLAUDE.md with a short “News section” architecture note (tables, routes, bucket, admin location) consistent with how other subsystems are documented.

Implementation Notes

  • Prefer editing existing Phase 3–5 files over adding new ones; this is a refinement pass.
  • Don't gold-plate the image-orphan problem — a documented note + best-effort hero cleanup is sufficient for v1.
  • Re-verify draft privacy one final time end-to-end (RLS + 404) — it's the single most important correctness property of the feature.

Completion Criteria

  • Invalid saves show field-level errors, not crashes; publishing without a hero image is blocked server-side too.
  • Homepage, load-more, and detail pages all handle empty/error/end states gracefully.
  • Replacing a hero image cleans up (best-effort) the previous object.
  • Accessibility pass done: alt text, focus states, semantic markup, contrast in both themes.
  • List query uses the partial index and does not over-fetch body_markdown.
  • get_advisors shows no unresolved security/performance issues for the new tables.
  • Draft privacy re-verified end-to-end (public 404, admin preview only).
  • npm run check and npm run build pass; CLAUDE.md updated.

How to Validate

  1. Try to save an article with no title, a duplicate slug, and publish with no hero — confirm each is rejected with a clear message.
  2. Unpublish every article and load / — confirm the empty state; republish and confirm normal rendering.
  3. Replace a hero image and confirm (Storage dashboard) the old object is gone and the new one serves.
  4. Run Lighthouse/axe on / and a /news/<slug> — confirm no critical a11y violations and no layout shift from images.
  5. explain analyze the list query and confirm the partial index is used.
  6. Run get_advisors; resolve/annotate anything flagged.
  7. Final: npm run check + npm run build both green.
