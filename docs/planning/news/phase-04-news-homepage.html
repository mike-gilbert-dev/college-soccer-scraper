Phase 4: News Homepage & Scores Relocation

Project: News Section Phase: 4 of 6 Depends on: Phase 3 complete
⚠ Prerequisite: Phase 3 (Admin Authoring) must be complete so there are real published articles to render.

Overview

This phase makes News the site's front door. It relocates the existing scoreboard from / to /scores, builds the News list at / (one featured article — the most recent published — with streamlined cards beneath it and a “Load more” control), and updates global navigation. This is the highest-visibility change in the project, so it comes after the content tooling exists and before the per-article detail polish.

What Will Be Built

1. Relocate Scores to /scores

The current scoreboard is src/routes/+page.svelte + +page.server.ts. Move both to src/routes/scores/+page.svelte and src/routes/scores/+page.server.ts essentially unchanged.

  • Preserve query-param behavior (?date, ?gender, ?division, ?season) — it's copied verbatim.
  • The live-scores Realtime subscription and all logic move with it untouched.
  • Check for any hardcoded internal links to / that meant “scores” (e.g. game cards, breadcrumbs) and repoint them to /scores. Grep for href="/" and goto('/').

2. News list at /

New src/routes/+page.server.ts + +page.svelte:

  • Load: call listPublishedArticles(locals.supabase, { offset: 0, limit: 5 }). The first row (most recent) is the featured article; the next 4 are streamlined cards. (Featured = most recent published, per intake — no manual flag.) Return { featured, cards, hasMore, nextOffset }.
  • Featured block: large hero image, category label, title (h1-ish), dek, and relative date; links to /news/<slug>.
  • Streamlined cards: compact card — smaller image (or thumbnail), category, title, dek (truncated), date. Responsive grid (1 col mobile → 2 col → multi-col desktop), consistent with the site's max-w-5xl container and dense aesthetic.
  • Empty state: if there are no published articles, show a friendly placeholder (so the homepage never looks broken pre-launch).

3. “Load more” pagination

  • Endpoint src/routes/api/news/+server.ts (public, RLS-gated via locals.supabase): GET ?offset=&limit= → returns the next page of card-shaped published articles + hasMore.
  • Client: a Load more button appends the next batch. Initial batch after the featured fold is 4; each subsequent click loads 8 (per intake). Track offset in $state; hide the button when hasMore is false; show a loading state while fetching.
  • Because ordering is published_at DESC and offset-based, this is stable for a mostly-append-only feed. (A brand-new publish mid-scroll could shift by one; acceptable.)

4. Navigation & layout updates

  • src/lib/components/Navbar.svelte: change the first link from Scores → / to News → /, and add a Scores → /scores link (both desktop and mobile menus). Keep Teams / Ratings / Stats. Update the navLinkClass active-state paths accordingly.
  • Global stats/welcome box in src/routes/+layout.svelte: leave as-is (intake: keep it everywhere) — it will sit above the featured article. No change required, but verify it looks acceptable above the news layout.

5. Card component

src/lib/components/ArticleCard.svelte (runes) + optionally FeaturedArticle.svelte, reused by the homepage now and potentially the detail page's “more news” later. Props: the card-shaped article row. Handles image, category pill, title, dek clamp, and date formatting.

Implementation Notes

  • SEO / sitemap: the sitemap change (add /scores, articles) is handled in Phase 5 along with per-article SEO. But do a quick check now that moving /→/scores doesn't 404 anything referenced elsewhere.
  • data-sveltekit-preload-data="hover" is set on <body> — card links get prefetch for free.
  • Dates: use a small relative-time or toLocaleDateString helper consistent with the rest of the app.
  • Images: use hero_image_url from the row; add loading="lazy" on card images, eager on the featured hero. Constrain with object-cover and fixed aspect ratios to avoid layout shift.
  • Realtime not needed here — news isn't live-updating; don't add a subscription.

Key files to read before starting

  • src/routes/+page.svelte & src/routes/+page.server.ts — the current homepage/scoreboard being relocated.
  • src/lib/components/Navbar.svelte — desktop + mobile link lists to edit.
  • src/routes/+layout.svelte — global chrome (stats box) that stays.
  • src/lib/server/articles.ts — listPublishedArticles to consume.

Completion Criteria

  • Visiting / shows the News homepage: one featured article (most recent published) + up to 4 streamlined cards.
  • The scoreboard is fully functional at /scores with all filters and live scores intact.
  • “Load more” appends 8 more published articles per click and hides when none remain.
  • Navbar shows News (/) and Scores (/scores); active states highlight correctly; mobile menu matches.
  • No internal link still points to / expecting the scoreboard.
  • Empty state renders gracefully when no articles are published.
  • Drafts never appear in the list or the load-more results.
  • npm run check is clean; layout works in light and dark, mobile and desktop.

How to Validate

  1. Publish ~7+ articles (mix of dates) via the Phase 3 admin so pagination is exercisable.
  2. Load /: confirm the newest published is featured, the next 4 are cards, and a Load more button appears.
  3. Click Load more: confirm 8 more appear, in published_at DESC order, with no duplicates; button disappears at the end.
  4. Confirm a draft article never shows up anywhere in the list.
  5. Go to /scores: confirm date nav, gender/division/season filters, and live-score patching all work exactly as before.
  6. Click News and Scores in the navbar (desktop + mobile) and confirm routing + active highlight.
  7. Toggle dark mode and shrink to mobile width; confirm featured + cards remain readable and unbroken.
