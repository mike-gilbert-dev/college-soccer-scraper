Phase 2: Public Page Server Loads

Project: Sport-Specific Seasons Phase: 2 of 4 Depends on: Phase 1 complete
⚠️ Prerequisite: Phase 1 (Schema Migration) must be complete. The seasons table must have sport_code and division columns before this code will work.

Overview

Updates the four public-facing page server loads to resolve the correct season by filtering on sport_code and division in addition to label. Before this change, all sports share a single season row per label; after this change, each sport+division combination resolves to its own row with independent start/end dates. The pattern is a two-line addition in each file.

What Will Be Built

The change in all four files follows the same pattern. Every season lookup currently does one of two things:

  1. By label (explicit): .eq('label', seasonParam).single()
  2. Latest fallback: .order('start_date', { ascending: false }).limit(1).single()

Both must be updated to also filter by sport_code and division. The sportCode and division values are already in scope in every file from the URL params parsed at the top of the load function.

The universal change (apply to all 4 files)

// BEFORE
const seasonBase = supabase.from('seasons').select('id, label');
const { data: season } = await (seasonParam
  ? seasonBase.eq('label', seasonParam).single()
  : seasonBase.order('start_date', { ascending: false }).limit(1).single());

// AFTER
const seasonBase = supabase
  .from('seasons')
  .select('id, label, start_date, end_date')
  .eq('sport_code', sportCode)   // sportCode already in scope
  .eq('division', division);      // division already in scope
const { data: season } = await (seasonParam
  ? seasonBase.eq('label', seasonParam).single()
  : seasonBase.order('start_date', { ascending: false }).limit(1).single());
ℹ️ Adding start_date, end_date to the SELECT is important for the scoreboard page, which uses season.start_date and season.end_date in defaultDate(). The other pages don't use those fields but selecting them is harmless.

Implementation Notes

  • Do not change any query other than the season lookup in each file. The downstream queries (games, team_seasons, etc.) already filter by sport_code and division — they are correct as-is once the season resolves to the right row.
  • After the change, navigating to /?gender=W will resolve to the WSO D1 season (different start_date/end_date than MSO D1). This is the desired behavior.
  • The ?season= query param stays as a plain label string like "2025-2026". Sport and division always come from the other URL params. This was a deliberate design decision — do not change the param shape.
  • No changes are needed to .svelte files in this phase — the server loads already pass sport, division, and seasonLabel to the page, and none of those shapes change.
