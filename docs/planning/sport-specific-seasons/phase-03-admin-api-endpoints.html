Phase 3: Admin API Endpoints

Project: Sport-Specific Seasons Phase: 3 of 4 Depends on: Phase 1 complete
⚠️ Prerequisite: Phase 1 (Schema Migration) must be complete. All 9 endpoints below already receive sportCode and division as request parameters — they just need to pass them into the season lookup.

Overview

Updates the 9 admin tool API endpoints so their season lookups filter by sport_code and division in addition to label. All 9 endpoints already accept sportCode (or equivalent) and division as request params, so no interface changes are needed — only the internal Supabase query for the season row gains two additional .eq() filters.

What Will Be Built

The universal change

Every endpoint below has a pattern like:

// BEFORE
const { data: season } = await supabaseAdmin
  .from('seasons')
  .select('id, year, start_date, end_date')
  .eq('label', seasonLabel)
  .single();

// AFTER
const { data: season } = await supabaseAdmin
  .from('seasons')
  .select('id, year, start_date, end_date')
  .eq('label', seasonLabel)
  .eq('sport_code', sportCode)
  .eq('division', division)
  .single();

The sportCode and division variables are already parsed from the request in every endpoint. Check what the variable is named in each file before editing — some use sportCode, some use sport_code, some use division as a Number()-parsed param.

Implementation Notes

  • Read each file before editing to confirm the exact variable names for sport code and division. Some endpoints use sportCode, others may use sport_code or sport.
  • The division value arriving from the client is a string from URL params or a number from JSON bodies. Confirm parsing before using: for URL params use Number(url.searchParams.get('division') ?? 1); for JSON bodies Number(body.division).
  • Do not change the request parameter names or response shapes — this is purely an internal query filter change. The admin UI (Phase 4) already passes sportCode and division to all these endpoints.
  • No changes are needed to the conferences upsert logic in backfill and ingest/date. The conference upsert uses onConflict: 'ncaa_conference_id,season_id' — since season_id now encodes sport+division, separate conference rows are created automatically.
  • After this change, running the backfill for WSO D1 will correctly resolve to the WSO D1 season row, and all games, team_seasons, and conferences created will be correctly scoped to that season.
