Phase 1: Storage Bucket & Server Helpers

Project: Archive Raw JSON Phase: 1 of 3 Depends on: None (first phase)

Overview

Creates the private ncaa-raw-games Supabase Storage bucket via a SQL migration and adds a thin server-side helper module (src/lib/server/ncaa-archive.ts) that encapsulates all Storage interactions: computing object paths, uploading raw JSON, and listing already-archived dates. Phases 2 and 3 import from this module — nothing outside it should talk to Storage directly.

What Will Be Built

1. Migration: supabase/migrations/20260610000000_ncaa_raw_bucket.sql

Creates the private bucket by inserting into storage.buckets. The service_role key bypasses RLS automatically, so no storage policies are needed for server-side access. public = false ensures no unauthenticated URL access.

INSERT INTO storage.buckets (id, name, public)
VALUES ('ncaa-raw-games', 'ncaa-raw-games', false)
ON CONFLICT (id) DO NOTHING;

2. Server helper: src/lib/server/ncaa-archive.ts

Exports three functions. All use the existing supabaseAdmin client from src/lib/server/supabase-admin.ts.

archivePath(sportCode, division, seasonYear, contestDate) — pure function, no I/O. Converts a YYYY-MM-DD ISO date to the storage object key.

// archivePath('MSO', 1, 2025, '2025-12-15') → 'MSO/1/2025/12-15.json'
export function archivePath(
  sportCode: string,
  division: number,
  seasonYear: number,
  contestDate: string   // YYYY-MM-DD
): string {
  const [, mm, dd] = contestDate.split('-');
  return `${sportCode}/${division}/${seasonYear}/${mm}-${dd}.json`;
}

saveContestJson(sportCode, division, seasonYear, contestDate, data) — uploads raw JSON to Storage, overwriting any existing file. Serializes data as pretty-printed JSON for human readability.

export async function saveContestJson(
  sportCode: string,
  division: number,
  seasonYear: number,
  contestDate: string,   // YYYY-MM-DD
  data: unknown
): Promise<{ path: string }> {
  const path = archivePath(sportCode, division, seasonYear, contestDate);
  const body = JSON.stringify(data, null, 2);
  const { error } = await supabaseAdmin.storage
    .from('ncaa-raw-games')
    .upload(path, body, {
      contentType: 'application/json',
      upsert: true   // overwrite silently
    });
  if (error) throw new Error(`Storage upload failed for ${path}: ${error.message}`);
  return { path };
}

listArchivedDates(sportCode, division, seasonYear) — lists all object keys under a season prefix and returns them as YYYY-MM-DD strings.

export async function listArchivedDates(
  sportCode: string,
  division: number,
  seasonYear: number
): Promise {
  const prefix = `${sportCode}/${division}/${seasonYear}`;
  const { data, error } = await supabaseAdmin.storage
    .from('ncaa-raw-games')
    .list(prefix, { limit: 400 });   // a season has at most ~140 dates
  if (error) throw new Error(`Storage list failed for ${prefix}: ${error.message}`);
  return (data ?? [])
    .filter(f => f.name.endsWith('.json'))
    .map(f => {
      const [mm, dd] = f.name.replace('.json', '').split('-');
      return `${seasonYear}-${mm}-${dd}`;   // back to YYYY-MM-DD
    })
    .sort();
}

Implementation Notes

  • The Supabase .list() method returns objects with a name property that is just the filename portion (e.g. 12-15.json), not the full path. The prefix must be passed as the first argument.
  • upsert: true on the upload is the overwrite mechanism — no pre-check needed.
  • The migration uses ON CONFLICT DO NOTHING so it is safe to re-run (idempotent).
  • All numeric values in the path (division, seasonYear) are stored as-is in the key string. division=1 → folder named 1, not d1 or D1.
  • The limit: 400 on .list() is a hard cap. Supabase Storage paginates at 100 by default; passing a higher limit avoids silent truncation for long seasons. 400 safely exceeds any real season length.
