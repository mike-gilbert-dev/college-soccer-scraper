Phase 2: Archive API Endpoints

Project: Archive Raw JSON Phase: 2 of 3 Depends on: Phase 1 complete
⚠️ Prerequisite: Phase 1 (Storage Bucket & Server Helpers) must be complete before starting this phase. The ncaa-raw-games bucket and ncaa-archive.ts helpers must exist.

Overview

Adds two SvelteKit server routes under src/routes/api/archive/. The first handles archiving a single date (called once per date by the admin UI's client-side loop). The second returns which dates are already archived for a given sport/division/season (used by the admin UI's status check). The admin UI in Phase 3 calls both endpoints directly.

What Will Be Built

1. src/routes/api/archive/date/+server.ts — POST

Receives a single date, fetches the raw NCAA API response, and saves it to Storage. Returns a lightweight result the UI can display immediately.

Request body (JSON):

{
  sportCode:   string,   // 'MSO' | 'WSO'
  division:    number,   // 1 | 2 | 3
  seasonLabel: string,   // e.g. '2025' — looked up in seasons table
  contestDate: string    // YYYY-MM-DD
}

Success response (200):

{
  path:       string,   // e.g. 'MSO/1/2025/12-15.json'
  gamesCount: number,   // contests in the response (may be 0 for off-season dates)
  contestDate: string   // echoed back for the UI to match against its loop state
}

Error response (400 / 500):

{ error: string }

Server logic (pseudocode):

export const POST: RequestHandler = async ({ request }) => {
  const { sportCode, division, seasonLabel, contestDate } = await request.json();

  // 1. Look up season year from label
  const { data: season } = await supabaseAdmin
    .from('seasons')
    .select('year')
    .eq('label', seasonLabel)
    .single();
  if (!season) return json({ error: `Season not found: ${seasonLabel}` }, { status: 400 });

  // 2. Fetch raw NCAA API response
  const [yyyy, mm, dd] = contestDate.split('-');
  const ncaaDate = `${mm}/${dd}/${yyyy}`;   // NCAA expects MM/DD/YYYY
  const raw = await fetchRawContests({
    contestDate: ncaaDate,
    seasonYear: season.year,
    division,
    sportCode
  });

  // 3. Count contests for the response summary
  const contests = (raw as any)?.data?.contests ?? [];

  // 4. Save to Storage (overwrites if exists)
  const { path } = await saveContestJson(sportCode, division, season.year, contestDate, raw);

  return json({ path, gamesCount: contests.length, contestDate });
};
Note: No delay is applied server-side. The client controls the inter-request delay via setTimeout. This keeps each individual server request fast and stateless.

2. src/routes/api/archive/status/+server.ts — GET

Lists dates that are already archived in Storage for a given sport/division/season. Used by the admin UI's "Check status" button to show which dates still need scraping.

Query parameters:

?sportCode=MSO&division=1&seasonLabel=2025

Success response (200):

{
  archivedDates: string[],  // YYYY-MM-DD dates that have files in Storage
  seasonYear:    number,    // season.year, so the UI can build the full date range
  startDate:     string,    // season.start_date (YYYY-MM-DD)
  endDate:       string     // season.end_date   (YYYY-MM-DD)
}

Server logic (pseudocode):

export const GET: RequestHandler = async ({ url }) => {
  const sportCode   = url.searchParams.get('sportCode')   ?? 'MSO';
  const division    = Number(url.searchParams.get('division') ?? 1);
  const seasonLabel = url.searchParams.get('seasonLabel') ?? '';

  const { data: season } = await supabaseAdmin
    .from('seasons')
    .select('year, start_date, end_date')
    .eq('label', seasonLabel)
    .single();
  if (!season) return json({ error: `Season not found: ${seasonLabel}` }, { status: 400 });

  const archivedDates = await listArchivedDates(sportCode, division, season.year);

  return json({
    archivedDates,
    seasonYear: season.year,
    startDate:  season.start_date,
    endDate:    season.end_date
  });
};

Implementation Notes

  • Import fetchRawContests from $lib/server/ncaa-api — it already exists and handles the NCAA GraphQL request.
  • Import saveContestJson and listArchivedDates from $lib/server/ncaa-archive (built in Phase 1).
  • Import supabaseAdmin from $lib/server/supabase-admin for the seasons lookup.
  • Both endpoints are admin-only paths under /api/archive/. The existing src/routes/admin/+layout.server.ts protects the /admin UI, but these API routes are not under /admin. Add a session check in each endpoint consistent with how the other /api/scrape/ endpoints handle auth — check the existing endpoints for the pattern.
  • The date format conversion (YYYY-MM-DD ↔ MM/DD/YYYY) happens only in the POST endpoint. Everything outside the NCAA API call uses ISO format.

Completion Criteria

  • POST /api/archive/date returns 200 with { path, gamesCount, contestDate } for a valid date/season combination
  • After a successful POST, the file appears in the ncaa-raw-games Storage bucket at the expected path
  • Calling POST twice for the same date silently overwrites (no 409 or error)
  • GET /api/archive/status?sportCode=MSO&division=1&seasonLabel=2025 returns 200 with the correct archivedDates array including the date just posted
  • npm run check passes with no TypeScript errors

How to Validate

  1. Start the dev server: npm run dev
  2. In a browser or via curl, POST to http://localhost:5173/api/archive/date with body {"sportCode":"MSO","division":1,"seasonLabel":"2025","contestDate":"2025-10-11"}. Expect a 200 with gamesCount > 0 (Oct 11 2025 was a busy day).
  3. Confirm MSO/1/2025/10-11.json appears in the Supabase Studio Storage bucket.
  4. POST again for the same date — expect 200, no error, file updated timestamp changes in Storage.
  5. GET http://localhost:5173/api/archive/status?sportCode=MSO&division=1&seasonLabel=2025 — expect archivedDates to contain "2025-10-11".
