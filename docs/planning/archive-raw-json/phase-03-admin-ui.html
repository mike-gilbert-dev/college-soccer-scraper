Overview

Adds an "Archive" tool to the existing /admin panel. It lives as a new ViewId inside src/routes/admin/+page.svelte — the same file and pattern as Historic Backfill, Missing Dates, and the other admin tools. The tool has two phases of interaction: a status check (which dates are already archived) and an archive run (client-side loop calling the single-date endpoint once per date with a configurable delay).

3. Status check function — checkArchiveStatus()

Calls GET /api/archive/status and builds the archiveDates list by iterating every calendar day in the season's startDate→endDate range (not just the game dates — the archive stores every date regardless of whether games occurred).

async function checkArchiveStatus() {
  archiveChecking = true; archiveCheckError = ''; archiveDates = []; archiveChecked = false;
  try {
    const params = new URLSearchParams({
      sportCode: archiveSport,
      division: String(archiveDivision),
      seasonLabel: archiveSeason
    });
    const res = await fetch(`/api/archive/status?${params}`);
    if (!res.ok) throw new Error(`${res.status}: ${await res.text()}`);
    const { archivedDates, startDate, endDate } = await res.json();

    // Build full date range from season bounds (overrideable by archiveStart/archiveEnd)
    const start = archiveStart || startDate;
    const end   = archiveEnd   || endDate;
    const archivedSet = new Set(archivedDates);
    const rows: ArchiveDateRow[] = [];
    const cur = new Date(start + 'T00:00:00Z');
    const fin = new Date(end   + 'T00:00:00Z');
    while (cur <= fin) {
      const iso = cur.toISOString().slice(0, 10);
      rows.push({ date: iso, status: archivedSet.has(iso) ? 'archived' : 'missing' });
      cur.setUTCDate(cur.getUTCDate() + 1);
    }
    archiveDates  = rows;
    archiveChecked = true;
  } catch (e) {
    archiveCheckError = e instanceof Error ? e.message : String(e);
  } finally {
    archiveChecking = false;
  }
}

4. Archive run function — runArchive()

Loops through the dates in archiveDates, calling POST /api/archive/date for each, with a archiveDelay ms pause between calls. Updates each row's status in real time so the UI reflects progress as it happens.

async function runArchive() {
  archiveRunning = true; archiveRunError = '';
  const datesToScrape = archiveDates.filter(d => d.status === 'missing' || d.status === 'error');
  for (const row of datesToScrape) {
    // Mark as in-flight
    archiveDates = archiveDates.map(d => d.date === row.date ? { ...d, status: 'scraping' } : d);
    try {
      const res = await fetch('/api/archive/date', {
        method: 'POST',
        headers: { 'Content-Type': 'application/json' },
        body: JSON.stringify({
          sportCode:   archiveSport,
          division:    archiveDivision,
          seasonLabel: archiveSeason,
          contestDate: row.date
        })
      });
      if (!res.ok) throw new Error(`${res.status}: ${await res.text()}`);
      const { gamesCount } = await res.json();
      archiveDates = archiveDates.map(d =>
        d.date === row.date ? { ...d, status: 'done', gamesCount } : d
      );
    } catch (e) {
      archiveDates = archiveDates.map(d =>
        d.date === row.date ? { ...d, status: 'error', error: e instanceof Error ? e.message : String(e) } : d
      );
    }
    if (archiveDelay > 0) await new Promise(r => setTimeout(r, archiveDelay));
  }
  archiveRunning = false;
}

Implementation Notes

  • All new state and functions go inside the existing <script lang="ts"> block. Do not create new component files — keep it inline with the other admin tools.
  • The SeasonRow type is already defined in the script block; use it.
  • The $effect for auto-populating dates from the selected season must not overwrite user edits once the user has manually changed the dates. The simplest approach: only auto-populate when the season changes by tracking the previous season label.
  • The runArchive() loop only processes rows with status 'missing' or 'error'. Already-archived rows are skipped. This means re-running after an error only retries the failures.
  • Do not add a "stop" button in this phase — if the user needs to stop, they can close the tab. The loop will terminate naturally when all dates are processed.
  • The delay input allows 0 (no delay). This is intentional for local dev use — the NCAA API has no enforced rate limit for this volume of requests.
