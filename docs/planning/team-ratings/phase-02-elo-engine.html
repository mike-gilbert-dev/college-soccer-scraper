Phase 2: ELO Engine

Project: Team Ratings Phase: 2 of 6 Depends on: Phase 1 complete
⚠️ Prerequisite: Phase 1 (Ratings Schema) defines the row shape this engine produces. The engine itself does no DB I/O, but its output type must match what Phase 3 will upsert.

Overview

Builds the margin-of-victory ELO calculation as pure, side-effect-free TypeScript — no Supabase, no fetch, no $env. Given a chronologically ordered list of games and a map of starting (seed) ratings, it returns one rating row per team per game date plus the final ratings. Keeping it pure makes it deterministic, trivially testable, and reusable by the recompute pipeline in Phase 3.

2. src/lib/server/ratings/config.ts

export const ELO_BASE = 1500;          // mean / new-team rating
export const ELO_K = 24;               // base K-factor (tune later)
export const ELO_HOME_ADVANTAGE = 85;  // elo points added to home side's expectation
export const CARRYOVER_LAMBDA = 0.70;  // season-to-season regression toward mean

/** World-Football-ELO style margin-of-victory multiplier. */
export function goalDiffMultiplier(goalDiff: number): number {
  const g = Math.abs(goalDiff);
  if (g <= 1) return 1;
  if (g === 2) return 1.5;
  return (11 + g) / 8;       // 3 -> 1.75, 4 -> 1.875, ...
}

3. src/lib/server/ratings/elo.ts

Two exported functions:

// Regression-to-mean carryover: seed = BASE + LAMBDA * (priorFinal - BASE).
// teamSeasonIds with no prior rating seed at ELO_BASE.
export function buildEloSeeds(
  teamSeasonIds: number[],
  priorFinalByTeamSeasonId: Map<number, number>
): SeedMap;

// Pure sequential ELO over chronologically ordered games.
// Emits one RatingRow per team per game (post-game value), plus you can
// derive finals as the last row per team.
export function computeElo(games: GameInput[], seeds: SeedMap): RatingRow[];

Algorithm for computeElo

  1. Initialize a working map current: Map<number, number> from seeds (default ELO_BASE for any team not seeded).
  2. Sort games deterministically: by contestDate, then startTime (nulls last), then id. Never mutate the caller's array.
  3. For each game:
    • Skip if either score is null/NaN (defensive — pipeline should pre-filter to final games).
    • rHome = current(home), rAway = current(away).
    • Home-field: effHome = rHome + (neutralSite ? 0 : ELO_HOME_ADVANTAGE).
    • Expected: eHome = 1 / (1 + 10^((rAway - effHome)/400)); eAway = 1 - eHome.
    • Result: home win sHome=1, draw 0.5, loss 0 (soccer regular-season ties are real — handle equality).
    • mult = goalDiffMultiplier(homeScore - awayScore).
    • delta = ELO_K * mult * (sHome - eHome). Apply +delta to home, -delta to away (zero-sum).
    • Emit a RatingRow for each team with asOf = contestDate, the new value, incremented gamesPlayed, and meta capturing { k: ELO_K, mult, opp, delta }.
  4. Return all emitted rows. (Final rating per team = its last row; Phase 4's read function derives "current" via max as_of.)
Same-day multiple games: a team can play more than one game on a date. Each game emits a row with the same as_of. Because Phase 1's unique key is (team_season_id, system, as_of), the pipeline must keep only the last row per (team, as_of) before upserting — note this here so Phase 3 handles it. The intermediate same-day values are still computed correctly in sequence; only the stored snapshot is the day's final value.

Implementation Notes

  • Runes mode is irrelevant here (plain .ts), but the project is strict TypeScript — type everything, no any.
  • No imports from $env, @supabase/*, or $app/*. This module must be unit-testable in isolation.
  • Carryover matches teams across seasons by team_season_id only as a key — the actual prior-to-current mapping (same team_id, prior season) is resolved in Phase 3 where DB access exists, then passed in as priorFinalByTeamSeasonId. The engine stays ignorant of season boundaries.
  • Keep numbers as double precision-compatible floats; do not round mid-computation. Rounding (if any) is a display concern for Phase 4.

How to Validate

There is no test runner in the repo yet. Validate with a throwaway script run via npx tsx (do not commit it), or a temporary +server.ts you delete after:

  1. Two teams both seeded 1500, neutral site, home wins 1–0. Expect home ≈ 1512, away ≈ 1488 with K=24 (delta = 24*1*(1-0.5) = 12).
  2. Same but a 3–0 home win: mult = 1.75, delta = 21; home ≈ 1521, away ≈ 1479.
  3. Home win 1–0 with home advantage (non-neutral): home was already favored, so delta < 12 (it earned the expected result).
  4. buildEloSeeds([1], new Map([[1, 1700]])) → 1500 + 0.7*200 = 1640.
