Phase 3: Recompute Pipeline & Admin UI

Project: Team Ratings Phase: 3 of 6 Depends on: Phase 2 complete
⚠️ Prerequisite: Phases 1 (schema) and 2 (ELO engine) must both be complete. This phase wires the pure engine to the database and triggers it from the admin UI.

Overview

Connects the ELO engine to real data: an orchestrator reads final games for a (sport, division, season) scope, resolves season-to-season carryover seeds, runs the engine, and writes results to team_ratings via a clean delete-then-insert rebuild. A new admin endpoint and a "Ratings" sidebar section expose a manual Recompute button mirroring the existing Archive/Ingest tools.

What Will Be Built

1. Orchestrator — src/lib/server/ratings/recompute.ts

Exports recomputeRatings({ sportCode, division, seasonId, systems }). For ELO (Phase 3 only handles 'elo'; later phases extend the systems array):

  1. Load this season's final games for the scope: 
    supabaseAdmin.from('games')
  .select('id, contest_date, start_time, home_team_season_id, away_team_season_id, home_score, away_score, neutral_site')
  .eq('sport_code', sportCode).eq('division', division).eq('season_id', seasonId)
  .eq('status', 'final')
  .not('home_score', 'is', null).not('away_score', 'is', null)
  .order('contest_date').order('start_time', { nullsFirst: false }).order('id');
    Map rows into GameInput[].
  2. Resolve carryover seeds. Find the most recent prior season for this sport (a seasons row with a smaller start_date that has team_seasons in this sport). For each team_season in the current scope, look up the same team_id's final ELO in that prior season via get_current_ratings(priorSeasonId, sportCode, priorDivision, 'elo') joined back through team_seasons.team_id. Build priorFinalByTeamSeasonId, then call buildEloSeeds. Teams with no prior rating seed at ELO_BASE.
  3. Run computeElo(games, seeds).
  4. Collapse same-day rows: for each (teamSeasonId, asOf) keep only the last emitted row (the day's final value), since the table's unique key is (team_season_id, system, as_of).
  5. Rebuild, don't patch. In a single logical operation: delete all team_ratings rows for system='elo' whose team_season_id is in this scope, then bulk-insert the collapsed rows. This makes recompute fully deterministic and idempotent — games remain the only source of truth. Insert in chunks (e.g. 1000 rows) to stay within payload limits.
  6. Return counts: { system, gamesProcessed, teamsRated, rowsWritten }.
Why delete-then-insert instead of upsert: ELO emits a variable number of history rows (one per game date). An upsert leaves stale rows behind if a game is deleted or rescheduled. Deleting the scope first guarantees the stored history exactly reflects current games. The delete is scoped to this sport/division/season + system, so other scopes are untouched.

2. API endpoint — src/routes/api/ratings/recompute/+server.ts

POST handler following the exact shape of api/ingest/date/+server.ts:

  • Auth: const { user } = await locals.safeGetSession(); if (!user) error(401, 'Unauthorized');
  • Body: { sportCode, division, seasonLabel, systems?: RatingSystem[] } (default ['elo']).
  • Resolve seasonLabel → season.id via the seasons table (same as ingest).
  • Call recomputeRatings(...) and return json(result).

3. Admin UI — extend src/routes/admin/+page.svelte

  • Add a 'ratings' nav section to navSections with a tool { id: 'ratings-recompute', label: 'Recompute Ratings' }, and add 'ratings-recompute' to the ViewId union.
  • Add a matching {:else if activeView === 'ratings-recompute'} block: Gender / Division / Season selects (copy the bindings already used by the Archive panel) and a Recompute button that POSTs to /api/ratings/recompute and shows returned counts + any error in an Alert.
  • Use Svelte 5 runes ($state, $derived) consistent with the rest of the file. Reuse data.seasons already loaded by admin/+page.server.ts.

Implementation Notes

  • All server-side DB access uses supabaseAdmin (service_role) — see src/lib/server/supabase-admin.ts. Never the browser client.
  • The endpoint is admin-only by virtue of the safeGetSession() guard; /admin already sits behind auth via admin/+layout.server.ts.
  • Keep the recompute synchronous in the request — a full season is small (a few thousand games) and finishes in well under a second. No background job needed.
  • Division is sent as a number in the JSON body but is smallint in the DB; pass it straight to .eq('division', division) as the ingest endpoint does.

Completion Criteria

  • recomputeRatings exists and, for a scope with final games, writes ELO rows to team_ratings.
  • Running recompute twice in a row produces byte-identical table contents (idempotent rebuild).
  • Carryover works: a team present in two consecutive seasons starts season N seeded from season N−1's final ELO regressed toward 1500; a brand-new team starts at 1500.
  • The admin "Ratings → Recompute Ratings" panel exists, runs against the selected scope, and shows returned counts.
  • Unauthenticated POST to /api/ratings/recompute returns 401.
  • npm run check passes.

How to Validate

  1. In /admin, open Ratings → Recompute Ratings, pick MSO / Division I / a season with ingested final games, click Recompute. Expect a success response with non-zero gamesProcessed and rowsWritten.
  2. SELECT count(*) FROM team_ratings WHERE system='elo'; — non-zero.
  3. Spot-check a strong team: SELECT * FROM get_current_ratings(<seasonId>, 'MSO', 1::smallint, 'elo') ORDER BY rank LIMIT 10; — top teams should be plausible (good records, high ELO).
  4. Click Recompute again; confirm row count is unchanged and top-10 identical.
  5. Verify carryover by comparing a returning team's first as_of value in the new season against 1500 + 0.70*(prevFinal - 1500).
