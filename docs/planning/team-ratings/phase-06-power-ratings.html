Phase 6: Power Ratings

Project: Team Ratings Phase: 6 of 6 Depends on: Phase 5 complete
⚠️ Prerequisite: The recompute pipeline, ratings table, and public page (Phases 1–4) must exist; this phase adds the third and most involved system on top of them.

Overview

Adds a least-squares Power Rating (Massey-style): solve for a per-team strength value plus a global home-field term that best explains observed goal margins. Like RPI it is a whole-season batch producing one snapshot per recompute. It is sequenced last because it requires a small linear solver and the most tuning.

What Will Be Built

1. src/lib/server/ratings/power.ts

A pure function computePower(games: GameInput[]): RatingRow[] using a Massey least-squares model on capped margin:

  • Model: for each game, margin = homeScore - awayScore (capped to ±MARGIN_CAP, e.g. 5, to limit blowout influence). Predicted margin = rating[home] - rating[away] + homeAdv*(neutral ? 0 : 1). Solve for the rating vector r and scalar homeAdv minimizing squared error.
  • Normal equations: build the Massey matrix M (n×n, where M[i][i] = games played by i, M[i][j] = −(games between i and j)) and right-hand side p (cumulative capped margin per team, home-adjusted). Add one extra row/column for the home-field unknown, or estimate homeAdv as the mean home margin and subtract it first (simpler; document the choice).
  • Connectivity fix: the raw Massey matrix is singular (ratings are relative). Replace the last equation with the constraint sum(r) = 0 (or add a small ridge term lambda*I) so the system is solvable and ratings are centered at 0.
  • Solver: implement plain Gaussian elimination with partial pivoting in TypeScript — no external linear-algebra dependency. A per-division pool is a few hundred teams; an O(n³) dense solve is fine (well under a second).
  • Output: one RatingRow per team, value = rating (interpretable as expected goal margin vs. an average team on a neutral field), meta = { homeAdv, marginCap }, as_of = max contest date.
Center ratings at 0 (or rescale to a friendlier display range) so Power values read intuitively. Keep the raw solve precise; apply any display scaling in the page, not the stored value.

2. Config + wiring

  • Add POWER_MARGIN_CAP and optional POWER_RIDGE to config.ts.
  • Extend recomputeRatings to handle 'power' in systems, with the same delete-then-insert rebuild for system='power' rows.
  • Add a Power checkbox to the admin Recompute panel (now ELO / RPI / Power).

3. Surface on the public page

  • Add Power to the /ratings system toggle. Display to 1–2 decimals (e.g. +1.8 / -0.6). Reuse get_current_ratings(..., 'power').

Implementation Notes

  • Keep computePower pure and dependency-free. The solver is the only non-trivial bit — write it defensively (guard singular pivots; if a pivot is ~0 after the centering constraint, the pool is disconnected and the affected component should fall back to 0/NaN handling with a clear comment).
  • Disconnected schedules early in a season make Power unstable; like RPI, document that it is meaningful only once the pool is reasonably connected.
  • The per-division pool decision applies: cross-division opponents are outside the matrix, identical to RPI scoping.
  • If you later want all three numbers comparable, that is a display/normalization concern — out of scope here.

Completion Criteria

  • computePower returns one centered rating per team plus a sensible homeAdv in meta.
  • The Gaussian-elimination solver produces correct results on a known small system (verified against a hand-solved 3×3).
  • Recompute with all three systems populates ELO, RPI, and Power; re-running is idempotent.
  • /ratings toggles across all three systems with appropriate formatting.
  • npm run check and npm run build both pass.

How to Validate

  1. Unit-check the solver on a hand-solved 3×3 system before wiring it in.
  2. Recompute a completed season with Power enabled; confirm homeAdv is a small positive goal value (home teams score modestly more on average).
  3. On /ratings, confirm Power ordering broadly agrees with ELO and RPI for the top teams (the three should correlate without being identical).
  4. Verify centering: the sum (or mean) of Power ratings across the pool is ~0.
  5. Re-run recompute; confirm Power rows are unchanged (idempotent rebuild).
