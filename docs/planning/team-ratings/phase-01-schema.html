Phase 1: Ratings Schema

Project: Team Ratings Phase: 1 of 6 Depends on: None (first phase)

Overview

Establishes the database foundation for all three rating systems (ELO, RPI, Power). A single team_ratings table stores every rating as a snapshot keyed by (team_season_id, system, as_of), which gives us multi-system coexistence and full per-game history for free. Schema must land before any engine or UI work because everything downstream reads and writes this table.

What Will Be Built

One migration file: supabase/migrations/20260618000000_team_ratings.sql. It creates the ratings table, indexes, RLS + grants matching the existing convention, and a read-side SQL function for fetching current ratings.

1. The team_ratings table

CREATE TABLE team_ratings (
  id              bigserial PRIMARY KEY,
  team_season_id  bigint NOT NULL REFERENCES team_seasons (id) ON DELETE CASCADE,
  system          text   NOT NULL CHECK (system IN ('elo','rpi','power')),
  as_of           date   NOT NULL,         -- elo: the game's contest_date; rpi/power: recompute date
  value           double precision NOT NULL,
  rank            integer,                  -- rank within (season, sport, division, system) at as_of; null for intermediate elo rows
  games_played    integer NOT NULL DEFAULT 0,
  meta            jsonb,                    -- system-specific extras (e.g. elo: {"k":24,"gd":2,"opp":1532})
  computed_at     timestamptz NOT NULL DEFAULT now(),
  UNIQUE (team_season_id, system, as_of)
);

CREATE INDEX team_ratings_lookup_idx ON team_ratings (team_season_id, system, as_of DESC);
CREATE INDEX team_ratings_system_idx ON team_ratings (system, as_of DESC);

The UNIQUE (team_season_id, system, as_of) constraint is what makes recompute idempotent. ON DELETE CASCADE keeps ratings consistent if a team_season is ever removed. Note that scope (season/sport/division) is not duplicated here — it is reached by joining team_seasons, exactly like the standings query does.

2. RLS + grants (match existing convention)

Follow the same pattern used for team_seasons: enable RLS, add a public-read policy, grant the service_role full access, and grant the new sequence.

GRANT ALL ON TABLE team_ratings TO service_role;
GRANT USAGE, SELECT ON SEQUENCE team_ratings_id_seq TO service_role;
ALTER TABLE team_ratings ENABLE ROW LEVEL SECURITY;
CREATE POLICY "public read team_ratings" ON team_ratings FOR SELECT USING (true);
⚠️ Reminder from prior project learning: Supabase views need an explicit GRANT SELECT TO service_role because table grants don't cascade to views. team_ratings is a table, not a view, so the grants above are sufficient — but if you add any view on top of it later, grant it explicitly.

3. The get_current_ratings SQL function

Mirrors get_standings: returns the latest rating per team_season for a given scope and system, ranked. The public page and admin UI both consume this via .rpc().

CREATE OR REPLACE FUNCTION get_current_ratings(
  p_season_id  bigint,
  p_sport_code text,
  p_division   smallint,
  p_system     text
)
RETURNS TABLE (
  ts_id        bigint,
  value        double precision,
  rank         integer,
  games_played integer,
  as_of        date
)
LANGUAGE sql STABLE AS $$
  WITH latest AS (
    SELECT DISTINCT ON (tr.team_season_id)
      tr.team_season_id, tr.value, tr.games_played, tr.as_of
    FROM team_ratings tr
    JOIN team_seasons ts ON ts.id = tr.team_season_id
    WHERE ts.season_id  = p_season_id
      AND ts.sport_code = p_sport_code
      AND ts.division   = p_division
      AND tr.system     = p_system
    ORDER BY tr.team_season_id, tr.as_of DESC
  )
  SELECT
    team_season_id AS ts_id,
    value,
    RANK() OVER (ORDER BY value DESC)::int AS rank,
    games_played,
    as_of
  FROM latest;
$$;

GRANT EXECUTE ON FUNCTION get_current_ratings(bigint, text, smallint, text)
  TO anon, authenticated, service_role;
Computing rank in the read function (rather than persisting it on every row) keeps writes simple. The rank column on the table is reserved for RPI/Power snapshot rows where a single stored rank per recompute is convenient; ELO intermediate rows leave it null.

Implementation Notes

  • Use a new migration timestamp after the latest existing one (20260614000000). 20260618000000 fits today's date and ordering.
  • division is smallint in team_seasons; the function parameter must be smallint so the RPC signature matches how get_standings is called.
  • Do not add scope columns (season/sport/division) to team_ratings. Reaching them through team_seasons avoids denormalization drift and matches the existing model.

How to Validate

  1. Apply the migration (Supabase CLI locally, or the Supabase MCP apply_migration against the project).
  2. Run SELECT * FROM team_ratings; — expect zero rows, no error.
  3. Run SELECT * FROM get_current_ratings(1, 'MSO', 1::smallint, 'elo'); — expect zero rows, no error.
  4. Confirm the unique constraint: insert a dummy row twice with the same (team_season_id, system, as_of) and verify the second insert is rejected; then delete the dummy row.
