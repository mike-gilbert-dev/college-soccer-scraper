Phase 4: Public Ratings Page

Project: Team Ratings Phase: 4 of 6 Depends on: Phase 3 complete
⚠️ Prerequisite: Phase 3 must be complete so team_ratings contains ELO data to display.

Overview

Surfaces ELO to users. Adds a public /ratings route — a ranked, filterable table mirroring the existing standings page — that reads current ELO via the get_current_ratings RPC. This completes the ELO milestone: ingest → recompute → public display.

What Will Be Built

1. src/routes/ratings/+page.server.ts

Model it on src/routes/teams/+page.server.ts:

  • Read sport, division, season from url.searchParams with the same defaults (MSO / 1 / latest season by start_date).
  • In parallel: fetch team_seasons for the scope (joining teams for name + logo_url_dark/light and conferences for label), and call supabaseAdmin.rpc('get_current_ratings', { p_season_id, p_sport_code, p_division, p_system: 'elo' }).
  • Join the RPC rows (ts_id → value, rank, games_played) onto the team_seasons, sort by rank (teams with no rating sort last), and return a typed RatingStanding[] plus the conference list for the filter dropdown.

2. src/routes/ratings/+page.svelte

  • Svelte 5 runes; reuse the dense sports-table styling and the TeamLogo component already used on the teams page.
  • Columns: Rank, Team (logo + name, linked to /teams/[ncaa_team_id]), ELO (rounded to integer), GP. Show the selected sport/division/season filters as controls that update the query string (same UX as standings).
  • Include a short caption explaining ELO is updated when an admin recomputes, and that it carries over between seasons with regression toward 1500.

3. Navigation + SEO

  • Add a "Ratings" link to src/lib/components/Navbar.svelte alongside the existing nav items.
  • Add /ratings to the staticUrls array in src/routes/sitemap.xml/+server.ts (required by CLAUDE.md whenever a public route is added).
📄 CLAUDE.md, "SEO" section — adding a public route obliges updating sitemap.xml/+server.ts. Do not add /admin or /api routes there; /ratings is public and belongs in staticUrls.

4. (Optional, if quick) ELO trend

Because Phase 2 stores per-game history, a small sparkline of a team's ELO over the season can be added to the team detail page using the same pattern as PlayerFormChart.svelte. Treat as a stretch goal — only do it if the core table is solid. If skipped, note it for a future phase.

Implementation Notes

  • The page reads through supabaseAdmin in the server load, consistent with teams/+page.server.ts (which also uses the admin client server-side rather than relying on anon RLS).
  • Round ELO for display only (e.g. Math.round(value)); keep the stored value precise.
  • Match the existing filter UX exactly so the standings and ratings pages feel like one product. Consider linking between them.
  • Teams with zero rated games should still appear (seeded ELO ≈ 1500 or "—") so the table matches the standings roster — decide and be consistent; recommended: show them at the bottom with their seed value and GP 0.

Key files to read before starting

  • src/routes/teams/+page.server.ts and +page.svelte — the filter + join + table pattern to mirror.
  • src/lib/components/TeamLogo.svelte — logo rendering.
  • src/routes/sitemap.xml/+server.ts — where to register the new route.
  • docs/design.md — table density, color, and spacing conventions.

Completion Criteria

  • /ratings renders a ranked ELO table for the default scope (MSO / D-I / latest season).
  • Sport / division / season filters update the listing via the query string.
  • Team names link to their detail pages and logos render.
  • "Ratings" appears in the navbar and /ratings is present in sitemap.xml.
  • npm run check passes and the production build (npm run build) succeeds.

How to Validate

  1. Visit /ratings. Confirm the top of the table matches the strong teams you spot-checked in Phase 3.
  2. Change division and season via the filters; confirm the listing changes and the URL reflects the selection.
  3. Click a team name; confirm it navigates to the correct team page.
  4. Load /sitemap.xml and confirm /ratings is listed.
  5. Cross-check ranking order against the standings page — strong records should broadly correlate with high ELO (not identical, but sane).
