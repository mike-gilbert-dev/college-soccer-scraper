Phase 5: RPI

Project: Team Ratings Phase: 5 of 6 Depends on: Phase 4 complete
⚠️ Prerequisite: The recompute pipeline (Phase 3) and ratings table (Phase 1) must exist. RPI plugs into the same orchestrator and surfaces on the same page (Phase 4).

Overview

Adds the Rating Percentage Index as a second rating system. Unlike ELO, RPI is a whole-season batch aggregate, not sequential — so it produces a single snapshot per recompute (one row per team, as_of = the latest contest date in scope). It reuses the existing recompute endpoint and admin button; only a new compute module and a system toggle on the public page are needed.

What Will Be Built

1. src/lib/server/ratings/rpi.ts

A pure function computeRpi(games: GameInput[]): RatingRow[] implementing NCAA soccer RPI:

  • WP (Winning Percentage), 25% — NCAA soccer uses location-weighted results: a road win and a home loss count more than a home win and a road loss; ties count as half. Standard NCAA soccer weights: home win = 0.6, road win = 1.4, neutral win = 1.0, and the mirror for losses (home loss = 1.4, road loss = 0.6, neutral loss = 1.0); ties = 1.0 both ways. WP = weighted wins / weighted decisions.
  • OWP (Opponents' WP), 50% — average, over all of a team's games, of each opponent's winning percentage computed excluding games against the team in question, using unweighted W-L-T (per NCAA, OWP/OOWP use unweighted records).
  • OOWP (Opponents' Opponents' WP), 25% — average of each opponent's OWP.
  • RPI = 0.25*WP + 0.50*OWP + 0.25*OOWP, a value in [0,1].
Build adjacency once: for each team_season, the list of opponents (with location and result). Compute unweighted records, then WP (weighted), then OWP, then OOWP in three passes. Pool is the per-division scope, matching the chosen rating-pool decision — opponents outside the scope (e.g. a D-I team's D-II opponent) are excluded from the pool's OWP/OOWP, consistent with how standings are scoped. Note this exclusion explicitly in code comments.

2. Wire into the orchestrator

  • Extend recomputeRatings so systems may include 'rpi'. When present: run computeRpi over the same loaded games, set each row's as_of to the max contest_date in scope, set value to the RPI, meta to { wp, owp, oowp }, then delete-then-insert the system='rpi' rows for the scope (same rebuild pattern as ELO).
  • The admin Recompute panel should let the user choose which systems to run (checkboxes for ELO / RPI), defaulting to all. Pass the selection in the POST body.

3. Surface on the public page

  • Add a system toggle (ELO / RPI) to /ratings. RPI display is a 4-decimal value (e.g. 0.6314). Reuse get_current_ratings(..., 'rpi') — no new SQL needed.

Implementation Notes

  • RPI is undefined/unstable very early in a season (few games, disconnected schedules). Guard divide-by-zero (no decisions yet → WP 0 or skip). Document the behavior.
  • Keep computeRpi pure (no DB) like the ELO engine, so it's testable in isolation.
  • The exact NCAA soccer location weights have varied by era; the 0.6/1.4 home/road weighting is the widely used men's/women's soccer convention. Centralize them as named constants in config.ts so they're easy to tune if you later match an official published table.

Key files to read before starting

  • src/lib/server/ratings/elo.ts — the pure-function style and GameInput/RatingRow contract to follow.
  • src/lib/server/ratings/recompute.ts — where to branch on systems and reuse the delete-then-insert helper.
  • supabase/migrations/20260614000000_standings_fn.sql — reference for how W-L-T is derived from games (home/away score comparisons), useful for cross-checking RPI records.

Completion Criteria

  • computeRpi returns one row per team with value in [0,1] and meta containing WP/OWP/OOWP.
  • Recompute with systems=['elo','rpi'] populates both systems; re-running is idempotent.
  • OWP/OOWP correctly exclude the team's own games from opponents' records (verified on a small hand example).
  • /ratings can toggle between ELO and RPI and shows sensible rankings for each.
  • npm run check passes.

How to Validate

  1. Recompute a completed season with both systems selected.
  2. Construct a 3–4 team mini-example by hand (or a scratch script) and confirm WP/OWP/OOWP match a manual calculation, including the self-exclusion rule.
  3. On /ratings, toggle to RPI; confirm undefeated teams with strong schedules rank near the top and that values sit in [0,1].
  4. Compare the RPI top-25 against any published NCAA soccer RPI for that season as a sanity check (ordering should be broadly similar even if weights differ slightly).
