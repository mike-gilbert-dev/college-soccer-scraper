Overview

Adds an "Archive Raw Box Scores" tool to the existing /admin panel as a new ViewId, placed immediately below "Archive Raw Games" in the sidebar. The tool follows the same pattern as the game scraper: the user selects sport/division/season, checks how many box scores are already archived, then runs a date-by-date loop that fetches all box scores for each date and shows per-date progress in real time.

3. checkBsStatus()

Calls GET /api/archive/boxscore/status and builds the bsDates list — one row per calendar day in the date range, all initially 'pending'. The archived count is stored in bsArchivedCount for display in the summary line.

async function checkBsStatus() {
  bsChecking = true; bsCheckError = ''; bsDates = []; bsChecked = false;
  try {
    const params = new URLSearchParams({
      sportCode: bsSport,
      division:  String(bsDivision),
      seasonLabel: bsSeason
    });
    const res = await fetch(`/api/archive/boxscore/status?${params}`);
    if (!res.ok) throw new Error(`${res.status}: ${await res.text()}`);
    const { archivedCount, startDate, endDate } = await res.json();

    bsArchivedCount = archivedCount;

    const start = bsStart || startDate;
    const end   = bsEnd   || endDate;
    const rows: BsDateRow[] = [];
    const cur = new Date(start + 'T00:00:00Z');
    const fin = new Date(end   + 'T00:00:00Z');
    while (cur <= fin) {
      rows.push({ date: cur.toISOString().slice(0, 10), status: 'pending' });
      cur.setUTCDate(cur.getUTCDate() + 1);
    }
    bsDates  = rows;
    bsChecked = true;
  } catch (e) {
    bsCheckError = e instanceof Error ? e.message : String(e);
  } finally {
    bsChecking = false;
  }
}

4. runBsArchive()

Loops date-by-date through bsDates, calling POST /api/archive/boxscore/date for each. Updates the row's status in real time. No inter-date delay is added client-side — the server already applies bsDelay between each box score fetch within a date, so the natural response time paces the loop.

async function runBsArchive() {
  bsRunning = true;
  for (const row of bsDates) {
    bsDates = bsDates.map(d =>
      d.date === row.date ? { ...d, status: 'scraping' } : d
    );
    try {
      const res = await fetch('/api/archive/boxscore/date', {
        method: 'POST',
        headers: { 'Content-Type': 'application/json' },
        body: JSON.stringify({
          sportCode:   bsSport,
          division:    bsDivision,
          seasonLabel: bsSeason,
          contestDate: row.date,
          delayMs:     bsDelay
        })
      });
      if (!res.ok) throw new Error(`${res.status}: ${await res.text()}`);
      const { contestsFound, saved, errors } = await res.json();
      bsDates = bsDates.map(d =>
        d.date === row.date
          ? { ...d, status: errors.length > 0 ? 'error' : 'done', contestsFound, saved, errors }
          : d
      );
    } catch (e) {
      bsDates = bsDates.map(d =>
        d.date === row.date
          ? { ...d, status: 'error', errors: [{ contestId: '', message: e instanceof Error ? e.message : String(e) }] }
          : d
      );
    }
  }
  bsRunning = false;
}
No client-side inter-date delay: Each POST request blocks until all box score fetches for that date complete (the server applies bsDelay between each). For a date with 10 games and 1000ms delay, the request takes ~10 seconds. This naturally paces the loop without needing an additional setTimeout on the client.

Implementation Notes

  • All new state and functions go inside the existing <script lang="ts"> block.
  • The SeasonRow type is already defined in the script block — reuse it for the $effect.
  • Since box score requests take longer per date than game requests (the server is making N NCAA API calls per date), expect the progress table to update more slowly than the game scraper. This is normal and expected.
  • The "Archive all" button should not be disabled based on bsArchivedCount — re-running always overwrites, so the count is informational only.
  • The bsDelay input controls the delay between individual box score API calls within each date (sent to the server). There is no separate client-side inter-date delay control — the server response time is the natural pacing.
