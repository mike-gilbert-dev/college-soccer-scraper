Phase 2: API Endpoints

Project: Archive Raw Box Scores Phase: 2 of 3 Depends on: Phase 1 complete
⚠️ Prerequisite: Phase 1 (Storage Helpers) must be complete. The four helper functions in ncaa-archive.ts must exist before these endpoints are built.

Overview

Adds two SvelteKit server routes under src/routes/api/archive/boxscore/. The POST endpoint handles a single date — it reads the archived game file for that date, fetches a box score for every contestId found, and saves each raw response to Storage. The GET endpoint returns a count of already-archived box scores for a season, used by the admin UI's status check. The admin UI in Phase 3 calls both endpoints directly.

What Will Be Built

1. src/routes/api/archive/boxscore/date/+server.ts — POST

Reads the game JSON file for one date, iterates every contestId, calls the box score API for each, saves the raw response. Returns a per-date summary the UI can display immediately.

Request body (JSON):

{
  sportCode:   string,   // 'MSO' | 'WSO'
  division:    number,   // 1 | 2 | 3
  seasonLabel: string,   // e.g. '2025-2026'
  contestDate: string,   // YYYY-MM-DD
  delayMs:     number    // ms to wait between individual box score fetches (default 1000)
}

Success response (200):

{
  contestDate:    string,   // echoed back for UI matching
  contestsFound:  number,   // contestIds extracted from the game file (0 if no game file)
  saved:          number,   // box score files successfully written to Storage
  errors:         { contestId: string; message: string }[]
}

Server logic (pseudocode):

export const POST: RequestHandler = async ({ request, locals }) => {
  const { user } = await locals.safeGetSession();
  if (!user) error(401, 'Unauthorized');

  const { sportCode, division, seasonLabel, contestDate, delayMs = 1000 } = await request.json();

  // 1. Look up season year
  const { data: season } = await supabaseAdmin
    .from('seasons').select('year').eq('label', seasonLabel).single();
  if (!season) return json({ error: `Season not found: ${seasonLabel}` }, { status: 400 });

  // 2. Read contestIds from the archived game file for this date
  const contestIds = await readGameContestIds(sportCode, division, season.year, contestDate);

  // 3. Fetch and save a box score for each contestId
  let saved = 0;
  const errors: { contestId: string; message: string }[] = [];

  for (const contestId of contestIds) {
    try {
      const raw = await fetchRawBoxScore(contestId);
      await saveBoxScoreJson(sportCode, division, season.year, contestId, raw);
      saved++;
    } catch (e) {
      errors.push({ contestId, message: e instanceof Error ? e.message : String(e) });
    }
    if (delayMs > 0 && contestId !== contestIds.at(-1)) {
      await sleep(delayMs);
    }
  }

  return json({ contestDate, contestsFound: contestIds.length, saved, errors });
};
No status filtering: Unlike the existing backfill, this endpoint archives a box score for every contestId regardless of game status. The NCAA box score API returns an empty or minimal response for scheduled/live games — that response is saved as-is. The ingestion step (a later project) will check data.boxscore for null before processing.

2. src/routes/api/archive/boxscore/status/+server.ts — GET

Lists how many box score files are already archived for a given season, plus the season's date bounds so the UI can build the date range. Does not scan game files — it only lists the boxscores/ prefix in Storage (one fast API call).

Query parameters:

?sportCode=MSO&division=1&seasonLabel=2025-2026

Success response (200):

{
  archivedCount: number,   // box score files already in Storage
  seasonYear:    number,
  startDate:     string,   // YYYY-MM-DD
  endDate:       string    // YYYY-MM-DD
}

Server logic (pseudocode):

export const GET: RequestHandler = async ({ url, locals }) => {
  const { user } = await locals.safeGetSession();
  if (!user) error(401, 'Unauthorized');

  const sportCode   = url.searchParams.get('sportCode')   ?? 'MSO';
  const division    = Number(url.searchParams.get('division') ?? 1);
  const seasonLabel = url.searchParams.get('seasonLabel') ?? '';
  if (!seasonLabel) error(400, 'seasonLabel is required');

  const { data: season } = await supabaseAdmin
    .from('seasons').select('year, start_date, end_date').eq('label', seasonLabel).single();
  if (!season) error(400, `Season "${seasonLabel}" not found`);

  const archivedIds = await listArchivedBoxScoreIds(sportCode, division, season.year);

  return json({
    archivedCount: archivedIds.length,
    seasonYear:    season.year,
    startDate:     season.start_date,
    endDate:       season.end_date
  });
};

Implementation Notes

  • Import fetchRawBoxScore and sleep from $lib/server/ncaa-api.
  • Import readGameContestIds, saveBoxScoreJson, and listArchivedBoxScoreIds from $lib/server/ncaa-archive.
  • Import supabaseAdmin from $lib/server/supabase-admin for the seasons lookup.
  • Both endpoints require authentication. Use the same locals.safeGetSession() pattern as src/routes/api/archive/date/+server.ts.
  • The delay (delayMs) is applied server-side between individual box score API calls within a single date. The client controls the delay between date-level requests via its own loop. This means for a date with 10 contests and delayMs=1000, the POST request will take ~10 seconds to respond — this is intentional and expected since the app runs locally.
  • Do not apply the delay after the last contest in a date to avoid unnecessary waiting at the end of each request.
