Phase 2: Roster Fetch & Raw Archive

Project: Roster Phase: 2 of 7 Depends on: Phase 1 complete
⚠️ Prerequisite: Phase 1 (Schema & Storage Foundation) must be complete — this phase writes to the sidearm-raw-rosters bucket and reads roster_sources.

Overview

This phase implements the "collection" step of the project — and only that step. Scraping (fetch + archive raw JSON) and ingestion (parse + match + enrich) are intentionally two separate functions; this phase builds the scraper. It fetches the external roster JSON for a verified source, archives the raw response to Storage as the immutable source of truth, and exposes typed parse/read helpers so the separate ingest function (Phase 3) and any re-runs can derive structured roster entries from Storage without re-fetching. No matching or writes to player tables happen here. This mirrors the fetch→archive split already used by nightly-ingest and ncaa-archive.ts.

What Will Be Built

1. Archive helpers — src/lib/server/roster-archive.ts

A sibling of src/lib/server/ncaa-archive.ts, providing:

  • rosterPath(sportCode, seasonYear, teamId) → 'MSO/2026/<teamId>.json' (pure function).
  • saveRosterJson(...) — upload raw JSON to sidearm-raw-rosters with { upsert: true }.
  • readStoredRoster(...) — download + JSON.parse a stored roster, returning the raw object or null if not found (copy the 404/Not-Found handling from ncaa-archive.ts).
  • listArchivedRosters(...) — list archived team IDs for a sport/season.

2. Sidearm types + parser — src/lib/server/sidearm.ts

Type definitions for the subset of the Sidearm /api/v2/Rosters/{id} response we use, plus a pure parseRoster(raw) that maps it to a normalized intermediate the matcher (Phase 3) consumes:

interface ParsedRosterPlayer {
  firstName: string;
  lastName: string;
  jerseyNumber: number | null;   // from jerseyNumber (string) -> int
  position: string | null;       // positionShort
  classYear: string | null;      // normalized from academicYearShort, see below
  height: string | null;         // `${heightFeet}-${heightInches}` or null
  hometown: string | null;
  headshotUrl: string | null;    // image.absoluteUrl
  externalRef: string | null;    // Sidearm player id if present
}

Class-year normalization maps Sidearm academicYearShort to the existing player_seasons.class_year vocabulary (FR/SO/JR/SR/GR): Fr.→FR, So.→SO, Jr.→JR, Sr.→SR, Gr./Grad→GR; redshirt prefixes (R-Sr.) strip to the base year (SR). Unknown values map to null and are logged, never guessed.

Skip players where the raw record's hide flag is true.

3. Fetch function

A function that, given a verified roster_sources row, builds the URL https://{domain}/api/v2/Rosters/{sidearm_roster_id}, GETs it with the project's standard User-Agent (Mozilla/5.0 (compatible; college-soccer-scraper/1.0)) and Accept: application/json, and returns the raw JSON. On non-2xx, throw with the status (logged by the caller).

4. On-demand trigger — edge function supabase/functions/roster-scrape/index.ts

Per the scheduling decision, this runs on demand (no cron). It accepts ?team=<ncaa_team_id> or ?source=<roster_source_id> to target a single source (default: all status='verified' sources for the active season, capped). For each target it does exactly three things: fetches → archives raw JSON to Storage → writes a roster_scrape_log row. Auth and structure copy nightly-ingest: verify_jwt:false, checks Authorization: Bearer <service role key> itself, resolves the active season from seasons, returns a JSON summary.

📌 Scrape and ingest are two separate steps. This phase builds only the scrape half — roster-scrape never parses into, matches against, or writes to players / player_seasons / roster_entry_queue. Parsing + matching + enrichment is a distinct function (roster-ingest) built in Phase 3 that reads the archived JSON back from Storage via readStoredRoster — it does not re-hit the external site. This mirrors how the NCAA pipeline splits nightly-ingest (fetch/archive) from nightly-reconcile (parse/match/upsert), so a matcher change can be re-run against already-scraped files without re-scraping, and a matching bug never costs a re-fetch.
📝 Edge vs. SvelteKit: Build the fetch/archive/parse logic in src/lib/server/ so it is unit-testable in the SvelteKit app, but the unattended runner is the edge function (Deno) — as with the NCAA pipeline. The edge function may inline a copy of the small pure helpers (the NCAA edge functions do this rather than importing app code).

Implementation Notes

  • Storage is the source of truth: always archive the raw response before any parsing, and upsert:true so re-runs overwrite.
  • parseRoster must be pure and total — never throw on a missing optional field; map to null.
  • Be polite: this hits a third-party site. Single request per source; if batching all sources, add a small delay/bounded concurrency (reuse the pool() helper pattern from nightly-reconcile, low limit e.g. 3).
  • Honor the existing scrape_log philosophy — every run, success or failure, writes a log row.

Key files to read before starting

  • src/lib/server/ncaa-archive.ts — the archive/read-helper pattern to mirror (path builder, upload, download-with-404-handling, list).
  • supabase/functions/nightly-ingest/index.ts — edge-function skeleton: auth check, season resolution, storage.upload, scrape_log insert, JSON summary response.
  • supabase/functions/nightly-reconcile/index.ts — the pool() bounded-concurrency helper and User-Agent/fetch conventions.

Completion Criteria

  • roster-archive.ts and sidearm.ts exist with the helpers and parser above; npm run check passes.
  • parseRoster correctly maps a real NC State response: 20+ players, each with firstName/lastName, and headshotUrl/classYear/height/hometown populated where present.
  • Class-year normalization produces only FR/SO/JR/SR/GR or null (verified against the NC State roster, including any R-Sr. case).
  • The roster-scrape edge function fetches NC State and writes the raw JSON to sidearm-raw-rosters/MSO/<year>/<teamId>.json.
  • A roster_scrape_log row is written with status='success' and entries_seen > 0.
  • No writes occur to players, player_seasons, or roster_entry_queue in this phase (scrape is strictly separate from ingest).

How to Validate

  1. Invoke the scraper for NC State: curl -H "Authorization: Bearer <service_role_key>" "https://<project>.supabase.co/functions/v1/roster-scrape?team=nc-state" (use the correct seoname).
  2. In the Supabase dashboard → Storage → sidearm-raw-rosters, confirm the archived JSON file exists at the expected path and contains the full roster.
  3. Run select * from roster_scrape_log order by created_at desc limit 1 — confirm success and a sane entries_seen.
  4. Re-run readStoredRoster + parseRoster against the stored file (a quick script or app route) and confirm the parsed array matches the live roster, including headshot URLs that resolve in a browser.
