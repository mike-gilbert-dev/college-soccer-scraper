Phase 4: Headshot Download & Storage

Project: Roster Phase: 4 of 7 Depends on: Phase 3 complete
⚠️ Prerequisite: Phase 3 (Matching Engine) must be complete — headshots can only be downloaded for player_seasons that have a matched player_id and a non-null external headshot_url.

Overview

Phases 2–3 capture the external headshot URL on player_seasons but never fetch the image itself. This phase downloads the actual headshot bytes and stores a durable, season-scoped copy in Supabase Storage so the app serves images from our own infrastructure (no hot-linking, no link rot). It is built as a third on-demand step after scrape and ingest — scrape (fetch JSON) → ingest (Storage→match, no external HTTP) → headshots (fetch images for matched players) — keeping each step single-purpose and independently re-runnable.

📌 Why a separate step, not part of ingest: ingest is defined as "no external HTTP" (it reads archived JSON from Storage). Downloading images is external HTTP, but it also requires the player_id that only exists after matching. A dedicated roster-headshots step satisfies both: it runs after ingest, makes the only external image calls, and can be re-run on its own (e.g. to backfill newly-approved players or retry failed downloads) without re-scraping or re-matching.

What Will Be Built

1. Migration — bucket + columns

  • A public Storage bucket player-headshots (public-read so the site can serve images directly; created with the same idempotent INSERT ... ON CONFLICT DO NOTHING pattern as the existing bucket migration, but public = true). Note this differs from the private ncaa-raw-games / sidearm-raw-rosters buckets — headshots are public-facing.
  • New columns on player_seasons (season-scoped, alongside the existing headshot_url): 
    alter table player_seasons
  add column headshot_path           text,        -- object key in player-headshots bucket
  add column headshot_downloaded_at  timestamptz,
  add column headshot_downloaded_from text;       -- the source URL we last fetched (change detection)

2. Storage path convention — extend roster-archive.ts (or a new headshot-storage.ts)

A pure path builder following the requested season-scoped hierarchy:

headshotPath(sportCode, season, division, teamId, playerId, ext)
  => `${sportCode}/${season}/${division}/${teamId}/${playerId}.${ext}`
  // e.g. 'MSO/2026/1/<teamId>/<playerId>.jpg'

Because the leaf filename is the player_id within a season/team folder, re-running produces the same key and overwrites in place — one headshot per player per season, latest ingest wins, trivially findable. The extension is derived from the downloaded image's content-type (image/jpeg→jpg, image/png→png, image/webp→webp); before writing, delete any existing <playerId>.* in that folder so a content-type change never leaves a stale duplicate.

3. The headshot runner — edge function supabase/functions/roster-headshots/index.ts

A new on-demand edge function (same auth/structure as roster-scrape / roster-ingest: verify_jwt:false, Bearer service-key check, season resolution, JSON summary). Same targeting params (?team= / ?source=; default all verified sources for the active season). For each target it:

  1. Selects player_seasons for the team-season that have a non-null headshot_url and need a download — i.e. headshot_path is null, OR headshot_downloaded_from ≠ current headshot_url (source changed), OR a ?force=true override.
  2. Resolves sportCode, season, division, team_id, and player_id for the path.
  3. Downloads each image with bounded concurrency (reuse the pool() helper) and the standard User-Agent; validates the response is an image content-type.
  4. Uploads to player-headshots at headshotPath(...) with upsert:true; sets headshot_path, headshot_downloaded_at = now(), headshot_downloaded_from = headshot_url.
  5. Writes a roster_scrape_log row (reuse the table; populate counts — e.g. enriched = images stored — and error_message on failure).

4. Connect images back to players

After this step a matched player's season row carries both the source URL (headshot_url) and our durable copy (headshot_path). The app builds the public URL as {SUPABASE_URL}/storage/v1/object/public/player-headshots/{headshot_path}. Storing the object key (not a full URL) keeps it portable across environments.

Implementation Notes

  • Politeness / scale: this fetches one image per matched player (thousands at full scale). Keep concurrency modest, add a small delay, and prefer the change-detection skip so routine re-runs only fetch new/changed images.
  • Fault isolation: a single image 404 / hotlink block / non-image response must be logged and skipped, never abort the batch; leave the prior headshot_path intact on failure.
  • Idempotent: re-running with no source changes downloads nothing and changes no rows.
  • Newly-approved players: queue entries approved in the admin surface (Phase 5) gain a player_season + headshot_url; the next roster-headshots run picks them up automatically via the selection in step 1.
  • Copyright/likeness: these are third-party photos stored on our infrastructure — keep the source URL as provenance; out of scope to adjudicate rights here, but flagged for awareness.

Completion Criteria

Every item below must be satisfied before proceeding to Phase 5.

  • Migration applies: public bucket player-headshots exists; player_seasons has headshot_path, headshot_downloaded_at, headshot_downloaded_from.
  • roster-headshots is a separate function from scrape/ingest and is the only step that downloads images.
  • Running it for NC State (after ingest) downloads each matched player's headshot to MSO/<season>/<division>/<teamId>/<playerId>.<ext> and sets headshot_path.
  • The stored image renders via its public URL in a browser.
  • Re-running with no source change downloads nothing (idempotent); changing a source URL (or ?force=true) re-downloads and overwrites the same key.
  • A failed image (e.g. 404) is logged and skipped without aborting the batch or wiping the existing headshot_path.
  • npm run check passes.

How to Validate

  1. Ensure NC State has been scraped (Phase 2) and ingested (Phase 3). Then invoke: curl -H "Authorization: Bearer <service_role_key>" "https://<project>.supabase.co/functions/v1/roster-headshots?team=nc-state".
  2. In Storage → player-headshots, confirm files exist under MSO/<season>/1/<teamId>/ named by player_id.
  3. Run select player_id, headshot_path, headshot_downloaded_at from player_seasons where headshot_path is not null and team_season_id = <ncstate ts id>; open 2–3 public URLs in a browser and confirm the right player's photo.
  4. Re-run the function; confirm the summary reports zero new downloads (idempotent).
  5. Temporarily point one row's headshot_url at a 404 and run with ?force=true; confirm an isolated error row in roster_scrape_log and that other downloads still succeed.
